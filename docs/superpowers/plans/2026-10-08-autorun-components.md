# Auto Run Components Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Scripts use named, reusable components (a widget or short flow with text and target inputs) that the runner expands when it runs, so fixing a component fixes every script.

**Architecture:**
- A new `Action::UseComponent` and a `LocatorStep.input` placeholder let scripts and components be stored as today's JSON.
- A per-project store (`autorun/components.rs`) holds components.
- The autorun runner expands `use_component` into ordinary actions before the browser layer sees them.
- The save route and a new component route reuse the discovery seen check and the repair gate's never-weakened rule.

**Tech Stack:** Rust (Tauri 2), React 19 + TS, vitest, tauri-specta.

**Spec:** `docs/superpowers/specs/2026-10-08-autorun-components-design.md`

## Global Constraints

- Every Rust test is an integration test in `src-tauri/tests/suite/<module>.rs`, with a `mod` line in `suite/main.rs`. Never use `#[cfg(test)]` in `src/`. A test touching process-wide state takes its lock from `suite/serial.rs`.
- `src/bindings.ts` is generated by `cargo test --test bindings`. Never hand-edit it.
- No HTTP DELETE to Azure DevOps.
- No secrets, hosts or query strings in files or logs. No `{{username}}`/`{{password}}` placeholders and no sign-in action inside a component.
- Component names are compared like area names: `nav::module_key` (case and spaces folded).
- A component's change cap is **3**. After it, the guide says to stop and report; the save is not blocked.
- Exact sentences:
  - "<name> is not saved in this project"
  - "<name> needs <input>"
- The guide, tool descriptions and command bodies never contain "read the source", "application's source" or "source-derived".
- Run one build or test command at a time (shared machine). No em or en dashes in code, comments, copy or commits.
- Commits: a Bash heredoc `git commit -F - <<'EOF'`, staged by name, ending with the implementer's `Co-Authored-By` line.
- The new tools ride the existing Auto Run gate (`ai_tools.rs` `autorun_offered_for`), mirrored in `src/lib/mcpTools.ts`.

## Review Focus

1. **A target input inside a chain** (`[{"css":"#grid"}, {"input":"row"}]`) must expand to the right chain, and the seen check must still check the fixed links. Task 3 test: `a_target_input_inside_a_chain_expands_in_place`.
2. **An old script saved before components** (no `use_component`, no `input` fields) must load and run unchanged. Task 1 test: `scripts_without_components_still_parse`.
3. **A component edited between a script's save and its run.** The run uses the current version and records it. Task 3 test: `a_run_records_the_version_it_used`.
4. **Text input values flowing into logs.** They follow the same masking as `fill` values today, and never appear unmasked in applog lines. Task 3 test: `a_failure_inside_a_component_never_logs_a_typed_value`.
5. **Removing a component a fixture uses.** Removal counts fixtures as users too. Task 6 test: `a_component_a_fixture_uses_cannot_be_removed`.

### Task 2: The component store

**Files:**
- Create: `src-tauri/src/autorun/components.rs` (`pub mod components;`).
- Test: `src-tauri/tests/suite/components.rs`.

**Interfaces:**
- Consumes: `recipe::project_slug`, `nav::module_key`, `ai_tools::atomic_write`.
- Produces (`Serialize, Deserialize, Clone, Debug, specta::Type`; `u64` fields exported as `f64` the way `discovery_map` does):
  - `pub struct Component { pub name, pub description, pub inputs: Vec<ComponentInput>, pub actions: Vec<Action>, pub tried_at: u64, pub tried_area: String, pub version: u32, pub changes: u32 }`
  - `pub struct ComponentInput { pub name: String, pub kind: InputKind, pub description: String }`
  - `pub enum InputKind { Text, Target }`, serialised as `"text"` / `"target"`.
  - `pub struct ComponentFile { pub components: Vec<Component> }`

  - `pub fn components_path(root, org, project) -> PathBuf` (`projects/<slug>-components.json`)
  - `pub fn load_components(root, org, project) -> Result<ComponentFile, String>`. A missing file is empty. A corrupt file errors with "the components file projects/<slug>-components.json could not be read; Reset it in Auto Run".

  - `pub fn put(root, org, project, c: Component) -> Result<(), String>`. It replaces by key, under one write lock, and writes only when the content changed.
  - `pub fn remove(root, org, project, name:&str) -> Result<(), String>`

  - `pub fn users_of(root, org, project, name:&str) -> Users`, where `pub struct Users { pub cases: Vec<i32>, pub fixtures: Vec<String> }`: case ids of saved scripts whose steps use it, and names of fixtures whose steps use it (see `autorun/fixtures*`).

### Task 3: Expansion when a script runs

**Files:**
- Modify: `src-tauri/src/autorun/components.rs` (expansion).
- Modify: the autorun runner, at the point each step's actions are executed (`runner::run_step_in_run` and the unattended replay's per-step loop in `autorun/replay.rs`; find both by content).
- Modify: the step-record type (`StepRecord` / `ActionOutcome` in `autorun/mod.rs` / `browser`) to carry `#[serde(default)] component: Option<String>` on outcomes, and a per-step `#[serde(default)] components: Vec<ComponentUse { name, version }>`.

**Interfaces:**
- Consumes: Task 1 and Task 2.
- Produces:
  - `pub fn expand(c:&Component, inputs:&serde_json::Map<String, Value>) -> Result<Vec<Action>, String>`:
    - text inputs replace `{{name}}` in string values;
    - target inputs replace a `LocatorStep` whose `input` names them. A target input that is a chain splices its links in place;
    - a declared input with no value errors with "<component> needs <input>";
    - a target given as a non-locator errors with "<component> needs <input> to be a locator".
  - `pub fn expand_step(root, org, project, actions:&[Action]) -> Result<(Vec<(Action, Option<String>)>, Vec<ComponentUse>), String>`:
    - a `UseComponent` becomes its expanded actions, each tagged with the component name;
    - an unknown component errors with "<name> is not saved in this project".
  - The runner calls `expand_step` before running a step's actions.
    - On error the step fails with that sentence, and no action runs.
    - Each outcome of an expanded action carries `component: Some(name)`.
    - The step record lists the `ComponentUse`s.
    - The masking applied to `fill` values in outcomes and logs applies to expanded actions unchanged.

### Task 6: Saving, changing and removing components

**Files:**
- Modify: `src-tauri/src/ai_bridge.rs`. Add the routes `POST /autorun-component-save {name, description, inputs, actions, why?}` and `POST /autorun-component-remove {name}`. Add both to `autorun_guard_for` and its guard test list.
- Reuse: the never-weakened comparison in `autorun/edits.rs`. If it only takes whole scripts, extract its per-step comparison into `pub fn weakens(old:&[Action], new:&[Action]) -> Option<String>` and call it from both.

**Interfaces:**
- Consumes: Tasks 2 to 5, plus `discovery_map::load_map` and `check_seen`.
- Produces the save rules, in order:
  1. Name and description are not blank.
  2. Inputs are unique by name. Every `{{x}}` and `{"input":"x"}` used is declared, and every declared input is used.
  3. No `SignIn` action, and no `{{username}}`/`{{password}}`.
  4. The actions' fixed locators pass `check_seen` against `tried_area` and the map, with placeholders exempt.
  5. `draft_fingerprint` of the sent component is in the open discovery session's `tried`; with no session, the save is refused with "Try the component live in discovery first".
  6. If the name exists: `why` is required, and `weakens(old.actions, new.actions)` must be None. Then `version + 1` and `changes + 1`.
  7. `tried_at` is now, and `tried_area` is the session's area.

  It returns `{saved, version, changes, cap_reached: changes >= CHANGE_CAP}`.
- Remove: refused while `users_of` is non-empty, listing the case ids and fixture names.
