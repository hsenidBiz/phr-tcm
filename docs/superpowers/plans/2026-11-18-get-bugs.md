# get_bugs Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Give assistants a read-only `get_bugs` tool that finds bugs on a PBI, by bug id, or on a test case, in the same way `get_test_cases` reads test cases.

**Architecture:** The tool takes the same path as `get_test_cases`:
- the MCP tool in `src-tauri/src/mcp.rs` calls the bridge route `GET /bugs` in a new `src-tauri/src/ai_bridge/bug_reads.rs`;
- the route reads Azure DevOps through new read-only functions in `src-tauri/src/ado/` (batched work item GETs with `$expand=relations`).

TCM files a bug with a `System.LinkTypes.Related` link to its test case, and a `System.LinkTypes.Hierarchy-Reverse` (parent) link to its PBI (`ado/endpoints.rs` `create_work_item`). So the bugs on an item are the linked work items whose type is the project's bug type (`detect_bug_type`).

**Tech Stack:** Rust (reqwest, serde_json), integration tests in `src-tauri/tests/suite/`.

**Spec:** `docs/superpowers/specs/2026-11-18-get-bugs-design.md`

## Global Constraints

- **Read only:** GET only, plus POST where an existing read already uses it. Never DELETE: `tests/suite/ado.rs` scans for it.
- **All Azure DevOps calls go through `src-tauri/src/ado/`.**
- **User and assistant facing errors name no URL:** log the raw error and return the `ado/transport.rs` sentences via `network_error`. `tests/suite/ado_network.rs` enforces this.
- **Caps:**
  - `limit` defaults to 5 and is capped at 20; `offset` pages through.
  - `titles_only` is capped at 200.
  - `bug_ids` takes at most 200 ids (reuse `case_reads::MAX_CASE_IDS` and `paging`).
- **Answer per bug:**
  - `id`, `title`, `state`, `reason`, `severity`, `priority`, `assigned_to` (display name), `tags`;
  - `area_path`, `iteration_path`, `created`, `changed`;
  - `repro_steps` and `system_info`, as plain text through `steps_xml::html_to_text`;
  - `linked_test_cases` and `linked_pbis`, as ids.
  
  `titles_only` returns `id`, `title` and `state` only.
- **Odd ids:** an id that is not a bug is listed under `not_a_bug`. With `pbi_id` and `bug_ids` both given, an id not on the PBI is listed under `not_on_pbi`.
- **Caching:** if anything is cached, it goes through `src-tauri/src/cache/`, with the key and time-to-live in `cache/keys.rs`. Never a private cache.
- **Tests:** Rust tests only in `src-tauri/tests/suite/`, with a `mod` line in `suite/main.rs`. Run single modules, one cargo command at a time.
- **Names:** hidden features are never named in commits or docs.
- **Scope:** the tool follows the same module and disabled-tool gating as `get_test_cases` (`ai_tools.rs`).

## Review Focus

1. **A PBI whose bugs sit only on its test cases** (filed from Run Tests with a Related link to the case and a parent link to the PBI, or with Related only) → the PBI query finds them, each listed once. Test in Task 1: `pbi_bugs_include_bugs_on_its_cases_once`.
2. **A project whose bug type is renamed** (for example "Defect") → that type is treated as the bug type, through `detect_bug_type`. Test in Task 1: `a_renamed_bug_type_is_still_a_bug`.
3. **A `bug_ids` list with a test case id in it** → that id comes back under `not_a_bug`, and the rest are read. Test in Task 1.
4. **Repro steps holding HTML, images or tables** → they arrive as readable plain text, never raw HTML. Test in Task 1.
5. **A transport failure** → the answer is a `network_error` sentence, with no URL. This is covered by the existing `ado_network.rs` scan plus one route test in Task 1.

### Task 1: Reading bugs from Azure DevOps and the `GET /bugs` bridge route

**Files:**
- Modify: `src-tauri/src/ado/endpoints.rs`, or a new `src-tauri/src/ado/bugs.rs` registered in `ado/mod.rs`. It reads:
  - an item's linked ids, using the relations of each work item;
  - the bug fields for a list of ids, in batches of `WORKITEM_BATCH_SIZE`.
- Create: `src-tauri/src/ai_bridge/bug_reads.rs`, holding `bugs(ctx, client, target)`, the same shape as `case_reads::test_cases`. Register it in `ai_bridge/mod.rs`'s route table as `("GET", "/bugs")`, with the same signed-in guard as `/test-cases`.
- Test: `src-tauri/tests/suite/bug_reads.rs`, plus its `mod` line. Follow however the existing `/test-cases` route or `ado` reads are tested (grep `tests/suite/` for `case_reads`, `test_cases`, the mock Azure DevOps server).

**Interfaces:**
- **Produces:**
  - `pub struct BugSummary` (Serialize, specta::Type only if a command needs it) with the fields listed in Global Constraints.
  - `pub async fn get_bugs_by_ids(&self, organization: &str, ids: &[i32]) -> Result<(Vec<BugSummary>, Vec<i32> /*not a bug*/), AdoError>`
  - `pub async fn linked_ids(&self, organization: &str, id: i32) -> Result<Vec<(String /*rel*/, i32)>, AdoError>`
  - The route query params are `pbi=<id>`, `case=<id>`, `ids=<csv>`, `limit`, `offset` and `titles_only`. At least one of `pbi`, `case` or `ids` is needed; without one, the route answers 400 with a plain sentence.
  - The answer is JSON `{ "bugs": [...], "total": n, "not_a_bug": [...], "not_on_pbi": [...] }`, with empty lists left out.

**How the route finds the bugs:**
- **`pbi`:** the PBI's linked items. Those that are bugs come in directly. For those that are test cases, through `is_tested_by_forward`, their own linked bugs come in too. Duplicates are dropped and the result is sorted by id, newest first.
- **`case`:** the case's linked bugs.
- **`ids`:** read as given. Combined with `pbi`, ids outside the PBI's bug set go to `not_on_pbi`.
