### Task 2: Item 72 - `when_hidden`, and a guard inside a guard

**Files:** `browser/actions.rs` (enum ~255, `check_guarded` ~904-943, NESTED_WHEN_VISIBLE ~898, `validate` ~1614, `each`/`judging` ~1761/1776, `targets*`, `execute_in` ~2676), `autorun/runner.rs` (`when_visible()` ~1845-1895, dispatch ~1370, ~54/828/976/1804), `autorun/seen_check.rs` (`takes_none` ~442, `seen_many` ~456, `guards` ~2387, `in_cleanup_guard` ~2551, `guarded_cleanup_notes` ~2194), `ai_bridge.rs` (`guard_finds` ~4114, `matched_targets`, `describe_action`), `autorun/{loading,components,case_values,env_copy,replay_to,forbidden_fixes,report,patterns}.rs` (each `WhenVisible` site from recon), `pw_export/translate.rs`, `autorun/guide.rs` (ACTION_KINDS, 306, 548-618, 576), `autorun/action_help.rs`, `src/screens/AutoRun/{describeAction.ts,ScriptEditor.tsx,CaseCard.tsx}`. Tests: `autorun_when_visible.rs`, `seen_check.rs`, `autorun_replay_to.rs`, `pw_export_translate.rs`, `autorun_guide.rs`, `action_help.rs`, `describeAction.test.ts`.

**Interfaces / decisions:**
- New variant `Action::WhenHidden { selector: Target, within_ms: Option<u32>, then: Vec<Action> }`, kind `when_hidden`. Same `within_ms` rules and `then` rules as `when_visible` (shared `check_guarded`).
- Runtime: the same wait `when_visible` makes (`shows_up_to_click`, `within_ms.unwrap_or(WHEN_VISIBLE_MS).max(WHEN_VISIBLE_FLOOR_MS)`), inverted: if the element shows at any point in the window the guard is skipped with `"<target> shown, skipped"` (new const `SHOWN_SKIPPED`); if it never shows, the `then` runs. It never acts on a first empty look.
- Nesting: one level. A `when_visible`/`when_hidden` may hold ONE level of `when_visible`/`when_hidden` in its `then`; a guard inside a nested guard is refused with `"a guard inside a guard's then cannot hold another guard - one level of nesting"` (replaces NESTED_WHEN_VISIBLE for scripts; the sign-in recipe's own rule in `recipe.rs:85` stays as it is). The inner guard's `then` has the same rules. Runner: an inner guard runs through the same guard function (boxed, as `guarded_in_pass` does at runner.rs ~1993); the outer guard's outcome detail lists the inner one's.
- Seen gate: `takes_none` is true for a `when_hidden` selector. `guards()` treats the selector of a guard at either depth as a guard selector (checked against every area). `in_cleanup_guard` covers `then` targets at either depth. Deferral rules are unchanged.
- Filing (`guard_finds`): files a `then`'s targets only when that guard acted (`when_visible` shown / `when_hidden` not shown); recurses one level into a nested guard and files its `then` only when the inner guard acted. To know that per guard, the guard runtime returns a small per-guard record (`GuardTrace { acted: bool, inner: Vec<GuardTrace> }` or equivalent) instead of guessing from the flattened detail text; `ActionOutcome` keeps its sentence.
- Playwright: `when_hidden` translates to the inverse of the `when_visible` translation (same timeout).
- Guide: the kind bullet; the pop-ups section explains `when_hidden` with the two backlog examples (apply Financial from the template when it is absent; rebuild a missing baseline group); nesting is one level.

- [ ] Step 1: failing tests - `when_hidden` runs its then when nothing shows (a ScriptedDriver page that never shows the target) and skips with `SHOWN_SKIPPED` when it shows; `when_hidden_waits_the_whole_window_before_acting` (the target appears at 400 ms of a 1000 ms window -> skipped); a nested guard validates and runs; a guard two levels deep is refused with the exact sentence; `then_holds_plain_actions_only` updated to the new rule; seen: a nested guard's selector is checked against every area; a clean-up's nested guard's then defers like a top-level one; `an_inner_guard_that_did_not_fire_files_nothing`; translation of `when_hidden`; guide kinds and help; describeAction kind list.
