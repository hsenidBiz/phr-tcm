- Defaults keep today's behaviour: `save` true, `timeout_s` 30, `end_autorun_discovery` now RELEASES by default (R88 is the one deliberate default change).
- `timeout_s`: integer 5..180, default 30; refusal names the range (R80).
- `db_query` per-cell cap 64 KB = 65536 characters; the marker is exactly `(truncated at 65536 characters)` (R89).
- `select_option` refusal lists at most 10 option labels; `discover_autorun_actions` stays at 20 actions per call (`MAX_BATCH`).
- Captures filter grammar is exactly `[?(@.FIELD=='value')]` / `[?(@.FIELD!='value')]`, one condition, string/number/boolean literal, dotted FIELD (R81).

## Review Focus

1. **A kept value leaking back.** A `keep` whose value also appears in the response body, a capture, an error detail or the log must show `{{var.name}}`, never the value (Task 3 test `a_kept_value_is_never_in_the_answer_or_the_log`).
2. **A replace that destroys someone else's template.** The R77 replace must only touch a template auto-saved by an earlier one-off of the SAME session and referenced by nothing; a template from another session, a proved one, or one a fixture/flow/setup uses gets the old behaviour (Task 1 test `a_template_from_another_session_or_in_use_is_never_replaced`).
3. **A timed-out POST disappearing from the change list.** A POST that timed out (page abort or DevTools wait) must still be noted as a save and answer that it may have been processed (Task 1 test `a_timed_out_post_is_noted_and_may_have_been_processed`).
4. **A signed-out answer shown as data, and the queue behind it.** A login page served 200 at the same URL (no redirect) must be caught, and the next call on that discovery refused without sending (Task 4 test `a_login_page_at_the_same_url_is_signed_out_and_the_next_call_is_not_sent`).
5. **Multi-line long text from `db_query`.** A view definition with line breaks and tabs longer than 256 characters must come back whole and in one cell (Task 8 test `a_multi_line_value_longer_than_256_comes_back_whole`).

Anything else inside `[?(...)]` -> `"capture path '{p}' has a filter it cannot read '[{inner}]' - one condition: [?(@.FIELD=='value')] or !="`.
- Filter semantics: over an array, keeps the elements whose `field` value equals the literal (string compared exactly; number compared numerically; a number-looking string does NOT equal a number); the rest of the path maps over the kept elements exactly as after `[*]` (one element left -> still a list of one, as `[*]` gives; empty -> `None`, so "capture {name} found nothing at {path}").
- Produces: `exec::apply_transforms(v: &Value) -> Result<Value, String>` - recursively replaces any object with exactly one key `$base64` by the base64 (standard, padded, UTF-8) of the JSON text of its value (a string value: its raw text, unquoted), and `$json` by the compact JSON text of its value as a string. Inner wrappers first. An object with `$base64`/`$json` plus other keys -> `Err("a $base64 or $json wrapper holds exactly one key")`. `build_request` calls it on the json body AFTER `substitute`, and on each form value that is an object (form values are text; a wrapper there is applied and its string used).
- `check(t)` runs the same shape rule statically on each step's `json`/`form` and reports `"step '{name}': a $base64 or $json wrapper holds exactly one key"`; placeholders inside wrappers are collected by `step_placeholder_names` as today (they are ordinary JSON leaves).
