# Guided Tour + Import Fixes Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Three changes that ship together. (1) Replace the static icon-and-caption walkthrough with a guided tour that drives the app through both areas on sample data, explains at most two things per tab in plain language, locks the app while it runs, and leaves nothing behind when it ends — Tasks 1-7. (2) Give the queue's main button a floating copy so a 100-case import does not have to be scrolled to the bottom to send — Task 8. (3) Let watched-file changes pile up in the report panel until the user clears them, instead of each save wiping the last — Task 9.

**Architecture:** A new `src/tour/` module owns the tour: the step script, the sample data, a reversible replacement of the app's data calls, and the overlay. `App.tsx` becomes the tour's host — it applies each step's destination (tab / Work Manager section), renders the toured screens against a throw-away React Query cache, suspends the on-disk cache and the saved-context writer while the tour runs, and restores all of it on exit. Screens are untouched apart from `data-tour` anchor attributes. The two import changes are local: a new `useOnScreen` hook plus a portalled copy of the primary action in `QueueSection`, and a per-file accumulating report in `ImportFile` measured from the queue and file contents captured when each pile started.

**Tech Stack:** React 19 + TypeScript, TanStack Query v5, Tailwind (theme tokens), Vitest + Testing Library, Tauri 2 (`src/bindings.ts` is generated — never edit it).

**Spec:** `docs/superpowers/specs/2026-09-02-guided-tour-design.md`

## Global Constraints

- **Plain language only.** No word about how the app works inside. Banned from all tour copy, and enforced by the jargon test in Task 4: `MCP`, `IPC`, `API`, `JSON`, `cache`, `caching`, `query`, `endpoint`, `binding`, `localStorage`, `repo`, `work item`, `payload`, `schema`, `backend`, `frontend`. Say "item" for a work item and "folder" for a repository. "AI Bridge" is the tab's name and stays.
- **At most two steps per tab.** AI Bridge is the single exception, allowed four.
- **Every step body is at most 160 characters**, one or two sentences.
- **Nothing the tour shows may persist.** No Azure DevOps call, no file, no saved setting. The user's tab, organisation, project, backlog item and Work Manager state are exactly as they were when the tour ends, however it ends.
- **`src/bindings.ts` is generated by Tauri Specta — do not edit it.** Fixtures must satisfy its exported types so `tsc` catches drift.
- **Never import `src/dev/`** from `src/tour/` or anywhere else that ships: `src/ui-consistency.test.ts` skips `dev/` because it never reaches a release build, and the demo module is deliberately excluded from release bundles.
- **Colours come from theme tokens** (`text-text`, `text-muted`, `text-faint`, `bg-surface`, `border-border`, `accent`, …). Raw hex or Tailwind palette colours fail `src/ui-consistency.test.ts`.

/**
 * Whether the guided tour has been seen, and whether it is running right
 * now. Kept apart from the tour itself so App, Settings and the command
 * palette can ask without pulling the walkthrough - and its sample data -
 * into the chunk the app loads at startup.
 */

const TOUR_DONE_KEY = "tcm-v2-tour-done";

/** Fired by Settings' "Show UI tour" button; App listens and reopens. */
export const START_TOUR_EVENT = "tcm-start-tour";

export function tourDone(): boolean {
  try {
    return localStorage.getItem(TOUR_DONE_KEY) === "yes";
  } catch {
    return true; // no storage -> never auto-run
  }
}

export function markTourDone(): void {
  try {
    localStorage.setItem(TOUR_DONE_KEY, "yes");
  } catch {
    // session-only
  }
}

// Running state lives in memory only: a tour interrupted by a crash must
// not come back locked on the next launch.
let running = false;
const listeners = new Set<() => void>();

export function setTourRunning(value: boolean): void {
  if (running === value) return;
  running = value;
  for (const cb of listeners) cb();
}

/** For useSyncExternalStore, and for plain guards in event handlers. */
export function tourRunningSnapshot(): boolean {
  return running;
}

export function subscribeTour(cb: () => void): () => void {
  listeners.add(cb);
  return () => {
    listeners.delete(cb);
  };
}
```

const SRC = join(dirname(fileURLToPath(import.meta.url)), "..");

function sources(): string {
  let text = "";

    for (const e of readdirSync(dir, { withFileTypes: true })) {

      if (e.isDirectory()) {

import { createPortal } from "react-dom";
import { Button } from "../components/ui/button";
import { IconBack, IconConfirm, IconNext } from "../lib/actionIcons";
import { TOUR_STEPS, type TourStep, type TourWhere } from "./tourScript";
import { markTourDone } from "./tourState";

const CARD_W = 340;
const CARD_H = 190; // estimate, for deciding whether the card fits below

/** How long to keep looking for a stop's area before showing the card on
 * its own. The screen has to mount and fade in first (120ms), and a slow
 * machine is allowed several times that. */
const ANCHOR_WAIT_MS = 1500;

/**
 * The guided tour: it walks the app itself - asking App to switch tab or
 * cross into the Work Manager - rings one area at a time and says what it
 * is for. Back and Next move; Skip tour (or Done at the end) closes.
 *
 * Nothing behind it can be clicked: App makes the whole shell inert while
 * this is up, and this layer sits above it in a portal.
 */
export default function UiTour({
  onNavigate,
  onClose,
  steps = TOUR_STEPS,
}: {
  /** MUST be stable (useCallback in the host) - it is an effect dep. */
  onNavigate: (where: TourWhere | undefined) => void;
  onClose: () => void;
  steps?: TourStep[];
}) {
  const [i, setI] = useState(0);
  const [rect, setRect] = useState<DOMRect | null>(null);
  const step = steps[i];
  const anchor = step?.anchor;
  const where = step?.where;

  // Send the app where this stop lives, then wait for the area to appear:
  // a tab switch has to mount and fade its screen in first.
  useEffect(() => {
    onNavigate(where);
  }, [onNavigate, where]);

  useEffect(() => {
    setRect(null);
    if (!anchor) return;
    const selector = `[data-tour="${anchor}"]`;
    const started = Date.now();
    let raf = 0;
    const look = () => {
      const el = document.querySelector(selector);
      if (el) {
        setRect(el.getBoundingClientRect());
        return;
      }
      if (Date.now() - started < ANCHOR_WAIT_MS) raf = requestAnimationFrame(look);
    };
    look();
    return () => cancelAnimationFrame(raf);
  }, [anchor]);

  // A resized window moves the area out from under its ring.
  useEffect(() => {
    if (!anchor) return;
    const onResize = () => {
      const el = document.querySelector(`[data-tour="${anchor}"]`);
      if (el) setRect(el.getBoundingClientRect());
    };
    window.addEventListener("resize", onResize);
    return () => window.removeEventListener("resize", onResize);
  }, [anchor]);

  const finish = useCallback(() => {
    markTourDone();
    onClose();
  }, [onClose]);

  if (!step) {
    finish();
    return null;
  }

  const pad = 6;
  const below = rect ? rect.bottom + CARD_H + 24 < window.innerHeight : true;
  // No area to ring (the opening and closing cards, or a screen that took
  // too long): the card sits in the middle and reads as a plain message.
  const cardTop = rect
    ? below
      ? rect.bottom + 12
      : Math.max(12, rect.top - CARD_H - 12)
    : Math.max(12, window.innerHeight / 2 - CARD_H / 2);
  const cardLeft = rect
    ? Math.min(Math.max(12, rect.left), Math.max(12, window.innerWidth - CARD_W - 12))
    : Math.max(12, window.innerWidth / 2 - CARD_W / 2);

  return createPortal(
    <div className="fixed inset-0 z-[100]" role="dialog" aria-label="Interface tour">
      {/* Swallows every click that is not on the card. */}
      <div className="fixed inset-0" onClick={() => {}} />
      {rect ? (
        <div
          className="pointer-events-none fixed rounded-lg border-2 border-accent transition-all duration-300"
          style={{
            top: rect.top - pad,
            left: rect.left - pad,
            width: rect.width + pad * 2,
            height: rect.height + pad * 2,
            boxShadow: "0 0 0 9999px rgba(0, 0, 0, 0.62)",
          }}
        />
      ) : (
        // Nothing ringed: dim everything, so the card still reads as the
        // only live thing on screen.
        <div className="pointer-events-none fixed inset-0 bg-black/60" />
      )}
      <div
        className="fixed space-y-2 rounded-lg border border-border bg-surface p-4 shadow-2xl transition-all duration-300"
        style={{ top: cardTop, left: cardLeft, width: CARD_W }}
      >
        <div className="flex items-baseline justify-between gap-2">
          <h2 className="text-sm font-semibold text-text">{step.title}</h2>
          <span className="shrink-0 text-xs text-faint">
            {i + 1} / {steps.length}
          </span>
        </div>
        <p className="text-sm text-muted">{step.body}</p>
        <div className="flex items-center gap-2 pt-1">
          <button className="text-xs text-faint hover:text-text" onClick={finish}>
            Skip tour
          </button>
          <div className="ml-auto flex gap-2">
            {i > 0 && (
              <Button variant="outline" size="sm" onClick={() => setI((n) => n - 1)}>
                <IconBack aria-hidden />
                Back
              </Button>
            )}
            {i < steps.length - 1 ? (
              <Button size="sm" onClick={() => setI((n) => n + 1)}>
                <IconNext aria-hidden />
                Next
              </Button>
            ) : (
              <Button size="sm" onClick={finish}>
                <IconConfirm aria-hidden />
                Done
              </Button>
            )}
          </div>
        </div>
      </div>
    </div>,
    document.body,
  );
}

 * For controls that get a floating copy while the real one is scrolled
 * out of reach: the copy shows while this is false, and stands down the
 * moment the real control is back on screen.
 *
 * Starts true, and stays true where there is no IntersectionObserver: a
 * floating button that cannot tell when to leave is worse than no
 * floating button at all.
 */
import { useEffect, useState, type RefObject } from "react";

export function useOnScreen(ref: RefObject<Element | null>, rootMargin = "0px"): boolean {
  const [onScreen, setOnScreen] = useState(true);

  useEffect(() => {
    const el = ref.current;
    if (!el || typeof IntersectionObserver === "undefined") return;
    const io = new IntersectionObserver(
      (entries) => setOnScreen(entries[entries.length - 1].isIntersecting),
      { rootMargin },
    );
    io.observe(el);
    return () => io.disconnect();
  }, [ref, rootMargin]);

  return onScreen;
}
```

## Task 9: Watched-file changes pile up until the user clears them

**Interfaces:**
- Consumes: `syncFromFile`, `SyncChange`, `fileName` from `lib/fileSync` (all already imported by the screen).
- Produces: nothing importable.

**How the accumulation is computed.** `syncFromFile(queue, prev, next)` measures changes queue-vs-file, so "everything since you last cleared" is exactly `syncFromFile(baseQueue, baseSnapshot, latestParse).changes`, where the two baselines are captured when the panel's group STARTS. One consequence to accept: if the user edits the queue in-app between two file saves, the accumulated report is measured against the queue as it was when the group started. That is the honest answer to "what has the file done since I last looked".
