# Run Order Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Implement the design in `docs/superpowers/specs/2026-09-23-run-order-design.md`: spec order in the Azure DevOps suite, a suggested run order in a `tcm-run-order.json` attached to the PBI, and each tester's own order on their machine, with Run Tests, the runner window and Suite Management using them as the design says.

**Architecture:** Rust gains a `run_order` module (the file's types, pure ordering helpers, reading and replacing the attachment) and two commands; `submit_queue` sets the suite order and writes the file after an upload that created cases. The frontend gains `src/lib/runOrder.ts` (reconcile, local My order, cross-window change event) used by Run Tests (order picker and reordering), the runner (Run next…) and Suite Management (a second editor for the suggested run order).

**Tech Stack:** Rust (Tauri 2, reqwest via `AdoClient`, wiremock tests), React 19 + TypeScript, vitest, Tauri events.

## Global Constraints

- Read the spec first; its terms (Spec order, Suggested run order, My order) and rules are binding. Shared orders change only in Suite Management and at upload; Run Tests and the runner change only My order.
- Every Rust test is an integration test under `src-tauri/tests/`. New wiremock tests use `MockServer::builder().start().await`, never `MockServer::start()` (pooled servers keep their URL between tests; see `tests/ado_boards.rs` `unshared_server`). One build or test command at a time; Rust from `src-tauri/` with `CARGO_TARGET_DIR=target/gate`.
- `src/bindings.ts` is generated by `cargo test --test bindings`; never hand-edit. After regenerating, `git diff --ignore-cr-at-eol --stat src/bindings.ts` shows only the intended additions.
- GET/POST/PATCH only against Azure DevOps. No DELETE anywhere. Replacing the file = upload + one PATCH (test rev, remove old relation(s), add new).
- User-facing errors name no URL: map transport errors through the sentences in `src-tauri/src/ado/transport.rs` as the rest of the code does.
- Caching: webview reads of the run-order file go through `persistentQuery` with a new key in `cacheKeys` (`src/lib/cache.ts`); no private caches. My order is a user setting (like case notes), not a cache.
- No em dashes in user-facing text. Colours via tokens; icons from `src/lib/actionIcons.ts`; dropdowns are the themed `Select`/`Combobox`; dialogs the shared `Modal`; `src/ui-consistency.test.ts` must not be weakened.
- The tour runs on sample data: every new command gets a stand-in in `src/tour/tourBackend.ts`.
- Commits via Bash heredoc with the model's own `Co-Authored-By` trailer. Changelog at release time.

pub const RUN_ORDER_FILE_NAME: &str = "tcm-run-order.json";
pub const RUN_ORDER_COMMENT: &str = "Test Case Manager run order";
pub const RUN_ORDER_FORMAT: &str = "tcm-run-order";
pub const RUN_ORDER_VERSION: u32 = 1;

#[derive(Debug, Clone, PartialEq, Serialize, Deserialize, specta::Type)]
pub struct RunOrderCase {
    pub id: i32,
    #[serde(default, skip_serializing_if = "Option::is_none")]
    pub group: Option<String>,
}

#[derive(Debug, Clone, PartialEq, Serialize, Deserialize, specta::Type)]
pub struct RunOrderFile {
    pub format: String,
    pub version: u32,
    pub saved_by: String,
    pub saved_at: String, // RFC 3339, UTC, e.g. 2026-09-23T10:15:00Z
    pub cases: Vec<RunOrderCase>,
}

#[derive(Debug, Clone, PartialEq, Serialize, Deserialize, specta::Type)]
#[serde(tag = "state", rename_all = "snake_case")]
pub enum RunOrderRead {
    None,
    Found { file: RunOrderFile },
    Unreadable { reason: String },
}

/// Parse one downloaded file. Wrong `format`, a `version` other than 1, or
/// invalid JSON -> Err with a one-sentence reason (no URL).
pub fn parse_run_order(text: &str) -> Result<RunOrderFile, String>;

/// The newest of several by `saved_at` (RFC 3339 strings in UTC compare as text).
pub fn newest(files: Vec<RunOrderFile>) -> Option<RunOrderFile>;

impl AdoClient {
    /// GET the PBI with relations; every AttachedFile relation whose
    /// attributes.name == RUN_ORDER_FILE_NAME is downloaded and parsed.
    /// None found -> RunOrderRead::None. Some parse, some do not -> the newest
    /// that parsed. None parse -> Unreadable{reason} (the first reason).
    /// Transport/auth errors -> Err(AdoError) as usual.
    pub async fn read_run_order(&self, org: &str, project: &str, pbi_id: i32) -> Result<RunOrderRead, AdoError>;

    /// Upload `file` as RUN_ORDER_FILE_NAME (POST _apis/wit/attachments), then
    /// ONE PATCH on the PBI: {"op":"test","path":"/rev","value":rev}, a
    /// {"op":"remove","path":"/relations/N"} for every existing run-order
    /// relation (highest index first), and {"op":"add","path":"/relations/-",
    /// "value":{"rel":"AttachedFile","url":<new>,"attributes":{"name":RUN_ORDER_FILE_NAME,"comment":RUN_ORDER_COMMENT}}}.
    pub async fn save_run_order(&self, org: &str, project: &str, pbi_id: i32, file: &RunOrderFile) -> Result<(), AdoError>;
}
```

export type OrderView = "suggested" | "spec" | "mine";
export type OrderKey = { org: string; planId: number; suiteId: number };

/** `order` kept where its ids are still in `spec`, duplicates dropped, then
 * every id of `spec` missing from it, in spec order. */
export function reconcile(order: readonly number[], spec: readonly number[]): number[];

/** `id` moved to directly after `afterId` (no-op if either is missing or equal). */
export function moveAfter(order: readonly number[], id: number, afterId: number): number[];

/** After position `idx`, the UNMARKED cases are re-sorted by `rank` into the
 * slots unmarked cases held; marked cases and everything at or before idx
 * stay where they are. Ids not in rank keep their relative order at the end
 * of the unmarked slots. */
export function resortUpcoming(list: readonly number[], idx: number, isMarked: (id: number) => boolean, rank: readonly number[]): number[];

export function loadMyOrder(k: OrderKey): number[] | null;          // localStorage `tcm-v2-run-order:${org}/${planId}/${suiteId}`; null when absent/unreadable/storage off
export function saveMyOrder(k: OrderKey, ids: readonly number[]): void; // stores, then emitMyOrderChanged(k)
export function clearMyOrder(k: OrderKey): void;                      // removes, then emitMyOrderChanged(k)
export function loadOrderView(k: OrderKey): OrderView | null;        // `tcm-v2-run-order-view:${org}/${planId}/${suiteId}`
export function saveOrderView(k: OrderKey, v: OrderView): void;

export const MY_ORDER_EVENT = "run-order:changed";
/** Fire-and-forget Tauri event (as src/lib/runnerBus.ts does); errors swallowed outside Tauri. */
export function emitMyOrderChanged(k: OrderKey): void;
export function onMyOrderChanged(cb: (k: OrderKey) => void): Promise<() => void>;
```
