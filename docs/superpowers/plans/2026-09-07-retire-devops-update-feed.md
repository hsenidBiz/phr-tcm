# Retiring the DevOps Update Feed Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The app reads updates from the public GitHub releases repo alone again, the Azure DevOps update source and everything the user could see of it are gone, and the source repository moves to a company-owned private GitHub repo.

**Architecture:** A removal, in a mandatory order. Tasks 1-4 take the DevOps source out of the app; that build ships as release **N**, published to **both** DevOps and GitHub, because installs on 1.23.x ask DevOps first and must be handed N through it. Only after N ships do Tasks 6-7 remove the publishing path. The `PHR-TCM` repository is never touched.

**Tech Stack:** Rust (Tauri 2, velopack 1.2), React 19 + TypeScript (vitest, Testing Library), PowerShell 5.1.

**Spec:** `docs/superpowers/specs/2026-09-07-retire-devops-update-feed-design.md`

## Global Constraints

- **`PHR-TCM` is never touched.** No push, no force-push, no branch deletion, no clone-and-commit. Its `releases` branch is deliberately left frozen at release N — that is what migrates a straggler months from now.
- **The releases repo does not move.** It stays `https://github.com/AvinAlwis/azure-devops-test-case-manager-v2-releases`, public. `$repoUrl` in `release-v2.ps1` is that repo and does not change.
- **Order is not negotiable.** Release N (Tasks 1-5) must be published to DevOps *and* GitHub before Tasks 6-7 remove the DevOps publishing path. Reversing it freezes every 1.23.x install permanently while the app reports itself up to date.
- **Nothing in Tasks 1-4 and 6-7 publishes a release, pushes a branch, or bumps a version.** Task 5 is the release and is user-gated.
- All Rust tests in this crate are integration targets under `v2/src-tauri/tests/` — never `#[cfg(test)]` modules in `src/`.
- `v2/src/bindings.ts` is generated by `cargo test --test bindings`. Never hand-edit it.
- `resolve` and `Attempt` in `updater/mod.rs` are **kept**. They are pure, tested decision logic and are not part of the DevOps work.
- Commits use a Bash heredoc — `git commit -F - <<'EOF' … EOF` — never PowerShell `-m`. End every message with `Co-Authored-By: Claude Opus 5 <noreply@anthropic.com>`.
- The machine is shared: run one build or test command at a time; never two suites at once.

    let mut attempts = Vec::new();
