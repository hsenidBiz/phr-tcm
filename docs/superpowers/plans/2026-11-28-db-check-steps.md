# Database Check Steps Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** add a read-only `expect_database` action to Auto Test scripts. It runs a stored SELECT through the SQL guard on the environment's database login, retries until its expectation holds, and reports what it expected and what it found.

**Architecture:**
- A new `Action` variant whose pure logic lives in a new `autorun/db_check.rs`:
  - validation;
  - placeholder binding as quoted literals;
  - sqlcmd row parsing;
  - expectation evaluation with redaction.
- The runner carries it the way it carries `expect_response`, against a database source on `InRun` built from the run's existing `PreconditionDb`.
- The save path, the guide, the Playwright export and the script editor each get their arm.

**Tech Stack:** Rust (Tauri 2, serde, specta), React 19 + TypeScript (vitest).

**Spec:** `docs/superpowers/specs/2026-11-28-db-check-steps-design.md`. Read it first: it is the authority.

## Global Constraints

- All paths are from the repository root `C:\Users\Admin\Desktop\Main Menu\Software\Personal Projects\Automated Test Cases Creator`. Run npm there. Run cargo in `src-tauri`.
- **Rust tests** go only in `src-tauri/tests/suite/<module>.rs` with a `mod` line in `suite/main.rs`. Never a `#[cfg(test)]` module in `src/`, and never a new file directly under `tests/`. Run one module with `cargo test --test suite db_check::`.
- **Commands.** One build or test command at a time. Never set `CARGO_TARGET_DIR`. Never stop processes by image name.
- **Bindings.** `src/bindings.ts` is generated by `cargo test --test bindings`. Never hand-edit it.
- **The SQL.** It must classify as `db::guard::Verdict::Read` (`guard::classify`). It is executed only through `StageDb::select` → `query::run_query(.., false, ..)`. Writes are never on for this action.
- **Placeholders.** Every placeholder in `sql` (`{{setup.x}}`, `{{fixture.id.x}}`, `{{noted.name}}`) becomes `setup_find::quoted_literal(value)` (`N'..'`), never raw text.
- **Timeout.** The default is `Timing.expect_ms` (10 000 ms), at most **60 000 ms**. The poll interval between queries is **500 ms**.
- **Secret columns.** A column whose name passes `capture_redact::secret_name` shows as `the hidden value` (`actions::HIDDEN_VALUE`) in every detail, report line, label and video mark.
- **User-facing text** names no URL, server, database name or login. It says "Auto Test", and no button label ends in `...` or `…`.
- **Commits.** Use a bash heredoc ending `Co-Authored-By: Claude Sonnet 5.5 <noreply@anthropic.com>`. Never stage `.superpowers/` or `.test-cases/`.
- **No HTTP DELETE anywhere.**

## Review Focus

1. **A captured value containing a quote or `'; DROP TABLE x --`** binds as one harmless literal, and the bound SQL still classifies as Read. Test in Task 1.
2. **A column value that is SQL NULL** (sqlcmd prints `NULL`). It is found as `NULL` and fails `equals "Approved"` with `found NULL`. It never panics or compares as empty. Test in Task 1.
3. **The query errors**, for example a bad column name or a syntax error from SQL Server. The step fails at once with the server's sentence (redacted, no server name). It does not retry for the full timeout. Test in Task 2.
4. **A `{{setup.x}}` inside `sql`** must not be substituted raw by `setup::substitute_steps`. It arrives at the runner as a quoted literal. Test in Task 2.
5. **Rows that contain tabs or very wide cells** (sqlcmd's `CELL_CAP` truncation). The column is found by header position, and the value comparison uses the printed cell. Test in Task 1 (a truncated cell compares as printed, and the failure says found `<printed>`).

- Produces, in `autorun/db_check.rs`:
  - `pub const MAX_TIMEOUT_MS: u32 = 60_000;`
  - `pub const POLL_MS: u64 = 500;`
  - `pub enum Expect { Exists(bool), Count { equals: Option<u32>, at_least: Option<u32>, at_most: Option<u32> }, Column { name: String, equals: Option<String>, matches: Option<String> } }`
  - `pub fn expectation(a: &Action) -> Option<Expect>`: `None` for other kinds.
  - `pub fn validate(sql: &str, e: Result<Expect, String>, timeout_ms: Option<u32>) -> Result<(), String>`. The rules:
    - the SQL is non-empty;
    - exactly one expectation group;
    - a column group has exactly one of `equals`/`matches`, and `matches` compiles as a regex;
    - the timeout is ≤ 60 000;
    - no placeholder sits inside quotes;
    - with placeholders replaced by `N'x'`, `guard::classify` is `Verdict::Read`;
    - a column group needs `ORDER BY` (case-insensitive, outside quotes).
  - `pub fn noted_names(sql: &str) -> Vec<String>`: the `{{noted.<name>}}` names in order.
  - `pub fn bind(sql: &str, lookup: impl Fn(&str) -> Option<String>) -> Result<String, String>`. It replaces each `{{setup.*}}`, `{{fixture.*}}` and `{{noted.*}}` placeholder whose full name (`setup.x`, `noted.y`) `lookup` answers with `quoted_literal(value)`. An unanswered name stays as written.
  - `pub fn unbound(sql: &str) -> Vec<String>`: placeholders still present.
  - `pub struct Rows { pub columns: Vec<String>, pub rows: Vec<Vec<String>>, pub capped: bool }`
  - `pub fn parse(text: &str) -> Result<Rows, String>`: the sqlcmd text as `setup_find::first_test_record` reads it. The header is split on `\t`, and column names are kept as printed and compared lowercased. The dash line and `(N rows affected)` footer are skipped. The `rows: N (capped)` prefix sets `capped`.
  - `pub enum Verdict { Pass(String), Fail(String) }`: each carries the detail sentence.
  - `pub fn judge(e: &Expect, rows: &Rows) -> Verdict`

  - `pub const READING_OFF: &str = "This step checks the database, but Database Access is turned off";`
  - `pub async fn run_check(src: &DbSource<'_>, a: &Action, noted: &BTreeMap<String, String>, timeout_ms: u32, cancel: Option<&AtomicBool>) -> ActionOutcome`
- Produces: `InRun { .., pub db: DbSource<'a> }`.

**What `run_check` does:**
1. A `Missing` source fails with `NO_DATABASE`. `ReadingOff` fails with `READING_OFF`.
2. It binds `{{noted.x}}` from `noted`:
   - a value starting with `browser::expect::NOTED_SECRET` fails with `a value read from a password field cannot be used in a database check`;
   - any `unbound` placeholder fails, naming it.
3. It loops `select` → `parse` → `judge` until a `Pass`, the timeout, or the cancel, sleeping `POLL_MS` between tries.
   - A `select` error that `query::is_unreachable` or `gate::unreachable` classify ends the loop early with `transport::`'s network sentence.
   - Any other `select` error, for example a syntax error or a bad column, fails **at once** with that error, passed through `capture_redact::redact_text`.
   - At the timeout, the last `Fail` detail is the outcome.
4. Each query goes to `applog` as `db_query`'s does, already done inside `run_query`. Nothing else is logged.
5. The unreachable outcome counts as a transient failure, not a suspected defect: add `expect_database` to `autorun/transient.rs`'s per-kind network-glitch handling, like an `api_request` network failure. Test: `unreachable_db_check_is_transient` in the same suite file.
