# Snappy UI Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make screen switches, data loads, and long lists feel instant during real use, without changing what any screen shows or when data is genuinely refreshed.

**Architecture:** Three independent levers. (1) The tab-switch fade drops from 300ms to 120ms. (2) The four ADO list queries that still lack a `staleTime` get 60s, so flipping between tabs renders from the React Query cache with zero network; spinners stay gated on "no data yet", and the one gate that leaks background refetches (Suites' scan bar) is fixed. (3) Long lists skip offscreen rendering via CSS `content-visibility: auto` (no virtualization library, DOM unchanged), and the queue's per-render diff recomputation is memoized.

**Tech Stack:** React 19, @tanstack/react-query v5, Tailwind v4 (utility in `index.css`), GSAP (AnimatedContent), vitest + Testing Library.

## Global Constraints

- **No refetch path may weaken.** Every existing `invalidateQueries` (mutations, Refresh buttons, `refreshSuite`, board move errors, drawer saves) and every imperative `refetch()` (the queue's `guardedSubmit` duplicate gate) bypasses `staleTime` by design — they must keep forcing network.
- **Spinners render only when a query has NO data** (`isLoading` / `isFetching && !data`), never during background refetches. Existing rows stay on screen while refreshing.
- **DOM stays complete.** `content-visibility` skips rendering work only; rows are never removed from the DOM. Tests asserting row presence/absence, drag-and-drop, and shift-range selection (which is index-based, not DOM-based, in every screen) must pass unchanged.
- **Do not touch `persistentQuery` internals** (`src/lib/persistentQuery.ts`) — Run Tests / Suites / board-PRs already do disk-seeded cached-first through it.
- **`content-visibility` never goes on `<tr>`** — table-internal boxes can't take size containment; the Run Tests and Suites point tables are explicitly out of scope for lever 3.
- Tests that count mockIPC calls exist in ViewCases (view/refresh_queue_html), RunPanel (ensure_pbi_suite), and WorkBoard (fetch_board across key changes) — all must stay green.

**Files:**

**Interfaces:**
- Consumes: nothing.
- Produces: `.cv-row` utility class; optional `--cv-size` CSS variable per list.

- [ ] **Step 1: Add the utility to index.css**

```css
/* Long-list rows: the browser skips layout and paint for rows outside the
   viewport, which is the difference between a 300-row list stuttering and
   scrolling clean. NOT virtualization - every row stays in the DOM, so
   selection, drag, tests, and Ctrl+F still see them. The intrinsic size is
   a pre-render height ESTIMATE for scrollbar stability; `auto` makes the
   browser remember each row's real height once rendered (so expanded
   rows/editors keep their true size). Never put this on <tr> - table rows
   cannot take size containment. */
.cv-row {
  content-visibility: auto;
  contain-intrinsic-size: auto var(--cv-size, 38px);
}
```

### Task 5: Memoize the queue's review diffs

**Files:**
- Modify: `v2/src/components/QueueSection.tsx` (~1050-1056 inside `queue.map`)
- Test: existing `QueueSection.test.tsx` review tests are the safety net (diff text, no-op badge, dup gate)

**Interfaces:**
- Consumes: `queue`, `currentById`, `prefs.moduleRef`, `prefs.preconditionsRef`, `reviewing`, `currentCases.isError`.
- Produces: `reviewRows: { diff: CaseDiff | null; diffFailed: boolean }[]` memo, indexed like `queue`.

Today `diffCase(tc, cur, ...)` runs for EVERY row on EVERY render while reviewing — typing in the inline editor or toggling a checkbox re-diffs an 80-case queue. Hoist it:

- [ ] **Step 1: Add the memo above the return**

```tsx
  // Diffing is word-level and runs per row - recomputing all of it on
  // every keystroke/selection render made an 80-case review sluggish.
  // Recomputed only when the queue, the fetched originals, or the field
  // refs actually change.
  const reviewRows = useMemo(
    () =>
      queue.map((tc) => {
        const cur = tc.update_id != null ? currentById.get(tc.update_id) : undefined;
        const diff =
          reviewing && cur
            ? diffCase(tc, cur, { moduleRef: prefs.moduleRef, preconditionsRef: prefs.preconditionsRef })
            : null;
        const diffFailed = reviewing && tc.update_id != null && !cur && currentCases.isError;
        return { diff, diffFailed };
      }),
    [queue, currentById, reviewing, prefs.moduleRef, prefs.preconditionsRef, currentCases.isError],
  );
```

- [ ] **Step 2: Use it in the row map**

Inside `queue.map((tc, i) => ...)` replace the inline `cur`/`diff`/`diffFailed` computation with `const { diff, diffFailed } = reviewRows[i];` (keep a local `cur` lookup only if later row code still needs it — check before deleting).
