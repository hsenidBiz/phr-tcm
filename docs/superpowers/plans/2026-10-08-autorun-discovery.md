# Auto Run Discovery Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The assistant discovers the live app in a browser it opens itself, the app keeps a per-area map of every locator it saw, and a script save refuses any locator the app never saw.

**Architecture:** Discovery reuses the supervised Auto Run browser slot (`commands/autorun.rs` `SESSION`), so the existing page, probe and try routes and the one-browser exclusion apply unchanged. Every locator the app serves or matches on a live page is recorded into `projects/<slug>-map.json` (new `autorun/discovery_map.rs`). A pure check (new `autorun/seen_check.rs`) runs in the save route after the floor gate.

**Tech Stack:** Rust (Tauri 2, CDP driver in `src-tauri/src/browser/`), React 19 + TS, vitest, tauri-specta bindings.

**Spec:** `docs/superpowers/specs/2026-10-08-autorun-discovery-design.md`

## Global Constraints

- Every Rust test is an integration test in `src-tauri/tests/suite/<module>.rs` with a `mod` line in `suite/main.rs`. Never `#[cfg(test)]` in `src/`. A test touching process-wide state takes its lock from `suite/serial.rs`.
- `src/bindings.ts` is generated by `cargo test --test bindings`. Never hand-edit it.
- No HTTP DELETE is sent by this app to Azure DevOps. Discovery never sends DELETE itself; a DELETE the page sends from a click is the page's request and is only logged.
- No secrets, hosts or query strings in logs or the map: the map stores address PATHS only, never fill values, never bodies or headers. Accounts are stored by key, never login.
- Stale: `explored_at` older than **30 days**, or a script failed in the area since it was explored.
- Matching: role + name compared case-insensitively with surrounding spaces trimmed and unusual spaces folded to a plain space; `text` and `css` exactly (after trim).
- The guide and tool descriptions must never again contain "read the source", "application's source" or "source-derived".
- Run one build or test command at a time (shared machine). No em or en dashes in code, comments, copy or commits.
- Commits: Bash heredoc `git commit -F - <<'EOF'`, staged by name, ending `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>` (or the implementer's model line).
- Discovery and the new tools ride the existing Auto Run gate (`ai_tools.rs` `autorun_offered_for`, dev build or Advanced Features).

## Review Focus

1. A page longer than the snapshot cap (300 lines): an element below the cap is never in a snapshot, so an honest script would be refused. A probe that matches records the locator (Task 4 test `a_matched_probe_records_a_locator_the_snapshot_cut_off`).
2. Names with non-breaking or doubled spaces, or a trailing newline, from the accessibility tree versus the same name typed in a script: must match (Task 1 test `seen_keys_fold_unusual_spaces_and_case`).
3. Two routes recording into the same map at once (a page read while a try records): both must be kept (Task 3 test `concurrent_recordings_both_survive`).
4. A discovery session the assistant never ends blocks every run: Close browser in the app and `auto_run_close_browser` must end it, and the refusal must say how (Task 5 test `close_browser_ends_a_discovery_session`).
5. A typed value or a query string leaking into the map (a fill into a password-looking field, a search URL): must never be stored (Task 3 test `the_map_stores_paths_and_locators_only`).

### Task 7: The save check

**Files:**
- Create: `src-tauri/src/autorun/seen_check.rs` (`pub mod seen_check;`)
- Modify: `src-tauri/src/ai_bridge.rs` `save_autorun_scripts` (:2929). The call goes between the floor loop's end (:3158) and `save_scripts_atomically` (:3161).

**Interfaces:**
- Consumes: Task 1 `Action::targets`, `Target::links`, `LocatorStep::seen_key`, `Action::typed_value`, `fold_name`. Task 3 `load_map`, `seen_keys`, `seen_paths`, `path_only`.
- Produces: `pub fn check_seen(map:&DiscoveryMap, script:&CaseScript, case_text:&[String], only_steps: Option<&[i32]>) -> Result<(), String>`. Rules, in step order:
  1. **Steps checked:** every step, or only those in `only_steps`.
  2. **Areas counted:** `script.area`, plus every area named by an area-visiting or `return_to_area` action in the script.
  3. **Every link of every target** must have its `seen_key` in `seen_keys(map, areas)`, unless one of two exceptions applies:
     - **(a) typed by the script:** the link's text or name contains, after `fold_name`, a value from `typed_value` of an action in an EARLIER step of this script. Values shorter than 3 characters are ignored.
     - **(b) from the test case:** the action is an expect/check kind (`Expect*`, `WaitFor`, and the table checks), and the link's text or name appears, after `fold_name`, inside one of `case_text` (the case's step actions and expected results).
  4. **`navigate`:** `path_only(url)` must be in `seen_paths(map)`.
  5. **The first failure is returned** as `"Step <n>: <describe> was never seen on the live app. Find it on the page first with probe_autorun_locator or discover_autorun_action, then save again."`, where `describe` is `Target::describe` or the navigate path.
- Wiring:
  - **Which scripts are checked:** for each prepared script, the check runs only when there is no saved script (a new script gets a full check), or when the sent script differs from the saved one (only that case's declared `edits` steps are checked). An unchanged resave is skipped.
  - **What it reads:** `load_map` once per save. A map read error refuses the save with that error.
  - **Where `case_text` comes from:** the `cases` the floor gate already fetched.
  - **On refusal:** HTTP 400 with the message; nothing is written.
