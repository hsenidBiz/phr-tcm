# Modules Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the single "Enable Advanced Features" switch with five per-machine modules (Database Access, Writing Style, Auto Run, API Templates, Playwright) arranged as a tech tree, chosen on a Modules page opened from Settings.

**Architecture:** A new Rust `modules` module owns the tree, the per-machine choice (`modules.json`), the upgrade from today's flags and every gate; `ai_tools::autorun_offered()` and `extras::features_on()` stop deciding anything. The webview gets a matching store (`src/lib/modules.ts`) that replaces `useAutoRunVisible`/`featuresOn`, a Modules page drawn from the approved mockup, and the help guide hides pages per module instead of with one `advanced` flag.

**Tech Stack:** Rust (Tauri 2, tauri-specta), React 19 + TypeScript, vitest, the docs-site build.

**Spec:** `docs/superpowers/specs/2026-10-15-modules-design.md`

## Global Constraints

- Modules, in code: `Module::{DbAccess, WritingStyle, AutoRun, ApiTemplates, Playwright}`, serialised snake_case (`db_access`, `writing_style`, `auto_run`, `api_templates`, `playwright`).
- Parents: DbAccess → Core; WritingStyle → Core; AutoRun → DbAccess; ApiTemplates → AutoRun; Playwright → AutoRun. Core is not a module and is always on.
- A module can be on only if its parent is on. Switching one off switches every module under it off.
- Fresh install: none on. Existing install (an `extras.json` or `app-settings.json` already in the app data dir when `modules.json` is first created): DbAccess and WritingStyle on, plus AutoRun, ApiTemplates and Playwright if `extras.json` had `advanced` or `unlocked` true. Development build (`ai_tools::dev_build()`), first creation: all on.
- Stored in `<app data>/modules.json`, written atomically like `extras.json`; not part of a backup.
- Off hides, never deletes: no data file is touched by switching.
- API Templates off does not stop a saved Auto Run script's setups and fixtures from running (`autorun/setup.rs`, `cleanup.rs`, `preconditions.rs` stay ungated); it hides the screen, its cards and its assistant tools.
- The Extras Easter egg (key sequence, Extras card, games, Reset to default) stays; `unlocked` no longer gates any feature. The Advanced Features switch, `get_advanced_features` / `set_advanced_features` and their webview helpers are removed (`extras.json` keeps reading `advanced` for the upgrade only).
- Busy refusals, verbatim: `Auto Run can't be switched off while a run is going - stop the run first.` and `Playwright can't be switched off while a repo command is running - stop it first.`
- Locked refusal, verbatim: `"<Module>" needs "<Parent>" switched on first.` (display names: Database Access, Writing Style, Auto Run, API Templates, Playwright).
- UI copy is sentence case; status lines exactly `On`, `Off · click to switch on`, `Locked · needs <Parent>`; the root is `Core` with `Test cases, suites, runs and the board`. Module descriptions verbatim from the spec.
- Colours only from theme tokens (`src/ui-consistency.test.ts` is a gate); icons from `src/lib/actionIcons.ts`.
- Rust tests only in `src-tauri/tests/suite/<module>.rs` with a `mod` line in `suite/main.rs`; tests touching the module state take a lock from `tests/suite/serial.rs`. `src/bindings.ts` is regenerated (`cargo test --test bindings`), never hand-edited.
- Help content never names the Easter egg (`docs-site/src/guard.test.ts` FORBIDDEN list holds).
- Build/test with `CARGO_TARGET_DIR=/d/azure-devops-test-case-creator/src-tauri/target-gate`; one build or suite at a time. Commits via Bash heredoc ending `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

## Review Focus

1. The upgrade: an existing install never loses something it uses; an unreadable `modules.json` on an existing install is rebuilt from `extras.json` again, never read as "everything off".
2. A module off is unreachable everywhere: sidebar, Ctrl+N shortcuts, command palette, a saved last tab (redirected only after the modules have loaded), assistant tool lists, the call-time refusal, bridge routes, slash commands, IPC commands, help pages.
3. The `--mcp` proxy sees a change without restarting: its policy comes from `/tools` on every list and call.
4. Switching Database Access off while Auto Run is on switches Auto Run, API Templates and Playwright off too, and the assistant's Auto Run tools refuse at once.
5. The Modules page works by keyboard and screen reader, and with reduced motion shows no travelling light or pulsing.

### Task 1: The module tree and its stored choice (Rust)

**Files:**
- Create: `src-tauri/src/modules.rs` (`pub mod modules;` in `lib.rs`)
- Modify: `src-tauri/src/lib.rs` (call `modules::init(dir)` right after `extras::init`)
- Test: `src-tauri/tests/suite/modules.rs`

**Interfaces:**
- Produces:
  - `#[derive(Debug, Clone, Copy, PartialEq, Eq, Hash, PartialOrd, Ord, Serialize, Deserialize, specta::Type)] #[serde(rename_all = "snake_case")] pub enum Module { DbAccess, WritingStyle, AutoRun, ApiTemplates, Playwright }` with `pub const ALL: [Module; 5]`, `pub fn parent(self) -> Option<Module>`, `pub fn name(self) -> &'static str` (display name), `pub fn children(self) -> Vec<Module>`, `pub fn below(self) -> Vec<Module>` (all descendants).
  - `pub fn initial(existing_install: bool, advanced: bool, unlocked: bool, dev: bool) -> BTreeSet<Module>`.
  - `pub fn load_or_create(dir: &Path, dev: bool) -> BTreeSet<Module>` - reads `modules.json`; when missing or unreadable, decides `existing_install` (an `extras.json` or `app-settings.json` in `dir`) and the old flags (`extras::load`, `extras::load_advanced`), saves `initial(...)` and returns it.
  - `pub fn apply(on: &BTreeSet<Module>, m: Module, want: bool) -> Result<BTreeSet<Module>, String>` - pure: switching on with the parent off is the locked refusal; switching off removes `m` and everything below it.
  - `pub fn init(dir: PathBuf)`, `pub fn on(m: Module) -> bool` (process-wide, `false` in the `--mcp` proxy like `extras`), `pub fn current() -> BTreeSet<Module>`, `pub fn set(m: Module, want: bool) -> Result<BTreeSet<Module>, String>` (save first, then publish, like `extras::set_advanced`).
