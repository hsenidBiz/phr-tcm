# Playwright Tab Follows Any Folder Layout - Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** TCM's Playwright tab (Runner, Overview, Sync, Export, Finish in repo) works with the repo's folders at any depth, including the new grouped `suites/<country>/<side>/<module>/[<group>/]<feature>/` layout.

**Architecture:** One new Rust module, `src-tauri/src/pw_repo/layout.rs`, holds every rule about the repo's folders (what a feature folder is, a spec's location, the navigation key, the owning project, a test-case file). Every other place calls it instead of counting segments. The webview types stop carrying fixed `country/side/module/feature` fields and carry `path: string[]` (folders from `suites/` down to the feature, the feature last).

**Tech Stack:** Rust (Tauri 2, serde, specta), React 19 + TypeScript, vitest.

**Spec:** `docs/superpowers/specs/2026-10-15-pw-any-layout-design.md`

## Global Constraints

- A **feature** is any folder under `suites/` that directly holds `specs/`, `test-cases/`, `pages/` or `data/`; its path is the folders from `suites/` down to it, any length. `_generated`, any folder starting with `_` or `.`, and `node_modules` are never part of the tree.
- The **first folder** names the Playwright project, uppercased; `common-components` (the shared tree) runs under `SL`.
- The **navigation key** is the last two folders of the feature's path, joined with `/` (`performance/rating-methods`, `definition-wizard/competencies`, `common-components/employee-search`).
- A feature's **test-case file** is `suites/<path>/test-cases/<feature>.md`, `<feature>` = the path's last folder.
- No check that the second folder is `admin`/`self` or that the country is `sl`.
- A folder name is valid when it is lowercase letters, digits and hyphens, not starting or ending with a hyphen and with no `--` (today's `is_kebab`).
- Saved placements from before this change (`{"side","module","feature"}`) read back as path `sl/<side>/<module>/<feature>`.
- Export still writes only the test-case file, `suites/_generated/<name>.spec.ts` and `suites/_generated/index.json`. Accounts tab unchanged. TCM never edits the repo outside what Export writes.
- Repo rules: every Rust test is in `src-tauri/tests/suite/<module>.rs` with a `mod` line in `suite/main.rs`; `src/bindings.ts` is regenerated by `cd src-tauri && cargo test --test bindings`, never hand-edited; colours via tokens only; `src/ui-consistency.test.ts` never weakened; one build/test command at a time (shared machine); never set `CARGO_TARGET_DIR`; commit with a bash heredoc `git commit -F - <<'EOF'`.

## Review Focus

1. `playwright --list` on Windows reporting `file` with `\` separators: a grouped spec must still be found (Task 2 test `a_backslash_path_is_located`).
2. A group folder that holds only feature folders must never be listed as a feature, so Export can never offer it and the Overview never shows a 0/0 group row (Task 1 test `a_group_folder_is_not_a_feature`).
3. An old saved placement with side `self` reads back as `sl/self/<module>/<feature>` and validates (Task 3 test `an_old_placement_reads_as_its_path`).
4. A typed placement with surrounding spaces, a trailing `/`, capitals or a single folder: trimmed where harmless, refused with a sentence otherwise (Task 3 test `a_typed_path_is_trimmed_or_refused`).
5. A case already exported into a grouped test-case file: Sync shows it Current (not Not in repo) and Update rewrites that same file (Task 1 test `a_grouped_case_is_in_the_repo`, Task 3 test `update_rewrites_a_grouped_file_in_place`).

- `impl Placement { pub fn validate(&self) -> Result<(), String>; pub fn seg(&self) -> &str; pub fn feature(&self) -> &str; pub fn navigation_key(&self) -> String; pub fn suggest(area_name: &str, features: &[Vec<String>]) -> Option<Placement> }`. `suggest` returns the feature whose last folder equals the area name in kebab case (today's conversion); the first by path order when several match; `None` when none does (the dialog then starts the row empty).
- `validate` refusals, verbatim: empty → `The path is empty.`; fewer than two folders → `The path "<path>" needs at least a country and a feature folder, such as sl/admin/performance/rating-methods.`; a bad folder → `The folder "<name>" must be lowercase letters, digits and hyphens, not starting or ending with a hyphen.`
- The dialog trims the typed text and a trailing `/` before saving; it never lowercases for the person.
- Export: `md_rel = suites/{seg}/test-cases/{feature}.md`; the navigation key checked against `repo.navigation_keys` is `placement.navigation_key()`. The test-case file's header line `**Side:** <side>` becomes `**Folder:** <seg>`.
