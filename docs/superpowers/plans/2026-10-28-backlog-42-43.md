### Task 1: Area walks: menu-shape variants, overlays, toggles, and a settled start

**Files:** `src-tauri/src/autorun/nav.rs` (`ModulePath`, `click_path`, `the_old_way`, `go_to_module_noted`, `reach_module_noted`, `PathFailure`), the area save route in `ai_bridge.rs` (`save_discovered_area` / `/autorun-area`) and the `save_autorun_area` schema in `mcp.rs`, `land_at_area` / `discover_start_in` in `ai_bridge.rs`, the guide's area text; tests in the nav / discovery suites.

**Produces:**
- `ModulePath` gains `#[serde(default)] pub variants: Vec<PathVariant>` with `PathVariant { clicks: Vec<..same click type..>, arrived: String }` (and whatever validation the primary path gets).
- `save_autorun_area` gains an optional `variant: bool`. With `variant: true` and an existing area of that name, the discovery's recorded clicks and arrival are appended as a variant (an identical one is not added twice); the answer says `saved as menu path <n> of "<area>"`. Without it, behaviour is unchanged.
- A walk: the primary path first; if it fails on a click that was never found (the item 41 condition), reload home and try each variant in order; the first that arrives wins and the walk's note says `reached "<area>" by its menu path <n>`. Only when every path failed does the failure carry the item 41 menu sentence, now ending `... script this area as an account whose menu has it, or record this account's path with save_autorun_area and variant: true.`
- Overlay: when a walk click fails because another element covers its target (find how the driver reports it, e.g. "covered by"/"intercepts"), wait for that cover to be gone (poll at `poll_ms`, at most `nav_ms`), then click once more. Still covered: fail as today.
- Toggle state: in `the_old_way`, before click n of the path (not the last), when click n+1's target is already visible, skip click n (the same rule the quick try already applies with `Skip::WhenNextIsReady`), so an expanded menu is not collapsed.
- `land_at_area`: after the walk, wait for the page to settle (the same load / idle wait a run uses after arriving) before the answer reads the page, so `path` / `page` describe where the browser is.

**Produces:**
- The probe counts every match (`matches: <n>`), its labels are 0-based and say `nth <i>` (matching the `nth` field).
- A Playwright pseudo-selector (`:text-is`, `:has-text`, `:text(`, `>>`) is refused with: `that is a Playwright selector, which Auto Run does not take: use a CSS selector or a role and name (see get_guide topic autorun, Selectors).`
- `show: "structure"` includes the matched element's parent (tag, id, classes, role, name). A new `show: "html"` answers each match's opening tag with its attributes (class included) and up to 300 characters of outer HTML, scripts and inputs' values left out.
- Name matching with `exact: true` compares trimmed names; when the only difference was whitespace, nothing more is needed. (State in the probe answer when the page's name has leading or trailing spaces.)
- Page answers are compact by default: the side menu / navigation landmark is answered in full only when it changed since this slot's last answer, else replaced by one line `side menu unchanged since the last answer`. A `page: "full"` argument (on discover, replay_to and get_autorun_page) gives the whole tree. `get_autorun_page` honours `query` (lines containing it, case-insensitive, with their ancestors) and a `within` with several matches uses the first and says how many there were.

### Task 4: Data a script needs is made, not held back (item 43)

**Files:** `src-tauri/src/autorun/roles/writer.md` (and any role that holds cases back), `src-tauri/src/autorun/guide.rs` (writer rules, "Hold the case back" wording), `src-tauri/src/ai_tools.rs` (`gen-tests` step 6 and the Several writers section's "held back" step), any code guard that refuses publishing or data creation for a writer (find it: grep publish / "person's word"), tests in `ai_tools.rs`, `autorun_guide.rs`, `autorun_roles.rs`.

**Produces (rule text, tightened to fit the cap):**
- A case whose precondition data is missing, or which uses up a shared state, is not held back: the writer (or a data builder it starts) makes what the case needs, by a proven API template or fixture (`run_api_template`, `run_api_fixture`) or by hand in the live app (explore discovery with `record_explore_change`), without asking, then scripts the case.
- Each case that consumes a state gets its own data (its own participant, record or cycle), so cases never fight over one record and a saver can replay twice.
- Limits kept: never alter or delete data the run did not create; make data through the app or API templates and fixtures only, never with your own SQL (`db_query` is for reading); names carry the environment's test prefix and read naturally; drafts stay drafts unless the case needs a published one, and only a cycle the run made may be published.
- The data made is listed in the run report and saved as a fixture (`save_api_fixture`) so it can be rebuilt.
- A case is held back only when making its data is impossible (no template and no way in the app), with that reason.
- The Several writers split no longer holds cases back for a role no free account has: it makes the account's role or record first (same limits), and holds back only what cannot be made.
- If a code guard refuses a writer's publish of a cycle the run created, change it to allow exactly that; otherwise text only.
