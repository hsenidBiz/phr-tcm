# Playwright Runner Speed - Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The Playwright Runner opens in about a second after a restart at any number of tests, shows the last tree while a changed clone is re-listed, and draws only what is on screen.

**Architecture:** The Rust cache gains a large-value tier (one file per key beside `cache.json`), which keeps the slimmed Playwright listing across restarts at any size; report counts move to the durable tier; the built tree is kept for the session. A new read-only command answers the kept tree and whether it is current, so the webview shows it at once and lists again behind it. The tree component folds to the feature level by default, remembers folds per clone, and draws through a virtual list.

**Tech Stack:** Rust (Tauri 2, serde, specta, sha2), React 19 + TypeScript, @tanstack/react-query, @tanstack/react-virtual (new), vitest.

**Spec:** `docs/superpowers/specs/2026-10-18-pw-runner-speed-design.md`

## Global Constraints

- One cache per side (CLAUDE.md): Rust caching only in `src-tauri/src/cache/`, every key and TTL in `cache/keys.rs`; webview caching only through `src/lib/cache.ts` (`cacheKeys`, `CACHE`). Never change an existing `cacheKeys` string.
- Both caches wipe on a different account's sign-in and on `clear`; the large-value files must go with them.
- A run, preview, debug run or dry count never uses a listing that is not the clone's current one (`runner::list(clone, false, ..)` keeps its meaning).
- Kept listing lifetime: 30 days (`PW_LIST_TTL`); the 1 MB in-memory-only limit (`PW_LIST_PERSIST_MAX`) is removed.
- Exact copy: updating line `Updating the test list - the repo has changed since it was last listed.`; disabled run reason `Wait for the test list to finish updating.`; the existing `Listing the tests…` stays for the no-tree case.
- Accessible names unchanged: `Tests` list, `Tick <label>`, `Fold <label>`, `Unfold <label>`.
- Repo rules: Rust tests only in `src-tauri/tests/suite/<module>.rs` with a `mod` line in `suite/main.rs`; `src/bindings.ts` regenerated by `cd src-tauri && cargo test --test bindings`; colours via tokens; `src/ui-consistency.test.ts` never weakened; one build/test command at a time; never set `CARGO_TARGET_DIR`; commits with `git commit -F - <<'EOF'`.

## Review Focus

1. Two windows (the main window and the separate Runner window) opening the Runner at once on a changed clone: exactly one Playwright listing runs, and both windows end up on the new tree (Task 2 test `two_requests_run_one_listing`).
2. A different account signs in after a listing was kept: the large file is gone from disk, not only from `cache.json` (Task 1 test `a_claim_by_another_account_removes_large_files`).
3. The Runner window while the tree is stale: Run, Preview and Debug are disabled there too, and a keyboard or command-palette run path cannot start one (Task 4 test `nothing_runs_while_the_tree_is_updating`).
4. Folds remembered for branches that no longer exist after a re-listing are ignored, and new branches take the default fold (Task 5 test `folds_for_gone_branches_are_ignored`).
5. A corrupt or half-written large file (crash mid-write) reads as absent and is relisted, never an error on screen (Task 1 test `a_damaged_large_file_reads_as_absent`).

### Task 1: The cache's large-value tier

**Files:**
- Modify: `src-tauri/src/cache/mod.rs` (store, `clear`, `claim_for`, `forget`, `evict_pw_lists`)
- Test: `src-tauri/tests/suite/cache.rs`

**Interfaces:**
- Produces:
  - `pub fn put_large<T: Serialize>(key: &str, value: &T)` - writes the value to `<cache dir>/cache/<first 32 hex chars of SHA-256(key)>.json` (temp file + rename) and records the key in the durable map as `{"large": "<name>"}` with the time; a store with no directory keeps the value in memory under the key.
  - `pub fn fresh_large<T: DeserializeOwned>(key: &str, ttl_ms: u64) -> Option<T>` - the value if recorded within `ttl_ms` and its file reads and parses; a missing or unparsable file forgets the key and answers `None`.

### Task 2: The kept listing, the kept tree and one listing at a time

**Files:**
- Modify: `src-tauri/src/pw_repo/runner.rs` (`list`, `kept_listing`, `build_tree` caller), `src-tauri/src/cache/keys.rs` (`PW_LIST_TTL` 30 days, remove `PW_LIST_PERSIST_MAX`, add `pw_tree(clone)`), `src-tauri/src/commands/pw_repo.rs` (new command), the command registration in `src-tauri/src/lib.rs`, `src/bindings.ts` (regenerated)
- Test: `src-tauri/tests/suite/pw_repo_runner.rs`

**Interfaces:**
- Consumes: Task 1's `put_large` / `fresh_large`.
- Produces:
  - `#[derive(Serialize, specta::Type)] pub struct KeptTree { pub tree: TestTree, pub current: bool }`
  - `pub fn list_kept(clone: &Path) -> Option<KeptTree>` - never starts a process: the kept listing (fresh within `PW_LIST_TTL`) built into a tree, `current` = its fingerprint equals the clone's now. Unlike `list`, a kept listing whose fingerprint differs is answered (as `current: false`), not forgotten.
  - Command `pw_list_kept(clone: String) -> Result<Option<KeptTree>, String>` (timed as `pw_list_kept`).
  - `list(clone, refresh, ..)` keeps its meaning (always the current listing) and now stores with `put_large`; only one listing of a clone runs at a time: a request arriving while one runs waits for it and then answers from the kept listing if its fingerprint now matches, without listing again.
  - `kept_listing` keeps only what `build_tree`, `owned` and `load_errors` read.
  - The built tree is kept in the session tier under `keys::pw_tree(clone)`, keyed by (fingerprint hash, newest report run id, `suites/_generated/index.json` modified time); a match skips `build_tree`.
