# Upload journal, Waiting for you, assistant activity Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Backlog A2 F6, F8, F9: an interrupted upload always comes back as the "Outcome unknown" hold; one **Waiting for you** list (Auto Run, sidebar count, bell) of what the assistant left for the person; an activity strip on every screen with Stop, and a **Recent activity** timeline.

**Architecture:** Rust writes a per-PBI journal before the first `$batch` and never deletes it; the webview turns a leftover journal into a hold through `saveHold` and clears it only after that. One Rust command gathers the waiting items from the three existing stores; divergence writes now emit `AutorunDataKind::Divergences`. `ai_bridge::route_timed` records curated assistant calls into a new `activity_log` kind, and the agents payload gains the sign-in trial; one React hook feeds both the Assistants card and the strip, which sits in `App.tsx`'s layout flow above `<main>`.

**Tech Stack:** Tauri 2, Rust (serde, tokio, tauri-specta), React 19 + TypeScript, TanStack Query, vitest + jsdom (`@tauri-apps/api/mocks` `mockIPC`).

**Spec:** `docs/superpowers/specs/2026-11-11-journal-inbox-activity-design.md`

## Global Constraints

- Every Rust test is an integration test in `src-tauri/tests/suite/`, one module per file, with a `mod` line in `suite/main.rs`; process-wide state takes a lock from `suite/serial.rs`.
- `src/bindings.ts` is generated by `cd src-tauri && cargo test --test bindings`; never hand-edit it.
- A tauri-specta command takes at most 10 arguments (`AppHandle` counts). `submit_queue` is already at 10, so new submit inputs go in `SubmitOptions`.
- No HTTP DELETE to Azure DevOps. F6 adds no network calls.
- Rust owns disk I/O and secrets; the frontend talks through generated bindings.
- Colours from tokens; icons from `src/lib/actionIcons.ts` (each `aria-hidden`); `src/ui-consistency.test.ts` must keep passing unweakened.
- Caching: plain `useQuery` for local Auto Run data (as `autorun-divergences` is); no new cache implementation on either side.
- User-facing text names no URL and no path; short active sentences, no em dashes.
- Auto Run and everything assistant-related appear only where Auto Run is available (`modules.has("auto_run")`); off, none of F8/F9 shows.
- Per-environment Auto Run data: the active environment only.
- Never name a hidden feature (UI copy, changelog, guide, commits). Crystal routes are never in the activity table.
- A hold or journal is lifted only by Check or Release (and a journal is cleared only after its hold is saved).
- Activity records hold time, label, group, fixed sentence, ok, case id, env id, org. Never a body field, query, URL, path, login, SQL or value.
- One build or test command at a time on this machine. One cargo cache (`src-tauri/target`); never set `CARGO_TARGET_DIR`.
- Commits: Bash heredoc `git commit -F - <<'EOF' … EOF`, last line `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

## Review Focus

1. **A remount or webview reload mid-upload must not turn a live upload into a hold.** The webview's `submitPhaseSnapshot()` covers a remount; a reload loses it, so Rust's running mark must answer `Running` and the retry must wait for `UploadEnded`. Tests: Task 2 "a remount mid-upload does not turn the journal into a hold", Task 2 "Rust saying running makes no hold", Task 1 `a_running_upload_reads_as_running_and_is_not_listed`.
2. **A crash anywhere between send and hold save leaves the journal.** Written before the first `$batch`, never deleted by Rust, cleared by the webview only after `applyOutcome` saved the hold. Tests: Task 1 `submit_queue_writes_the_journal_before_the_first_batch_and_never_clears_it` (source tripwire), Task 2 "the journal is cleared only after the hold is saved".
3. **No body, query or secret ever reaches a timeline record.** Tests: Task 6 `a_record_carries_no_body_or_query`, `a_record_has_exactly_the_allowed_keys`.
4. **The strip sits in the layout flow, never an overlay.** jsdom cannot see covering; a source tripwire plus the hand walk-through in Task 9. Test: Task 8 "the strip is in the layout flow above main".
5. **An account or org switch never shows another org's journals or activity.** Tests: Task 1 `another_account_never_sees_or_clears_a_journal`, Task 6 `the_timeline_shows_only_this_org_and_environment`.

- On disk: `{ "owner": "<cache::owner()>", "journal": UploadJournal }`. Key is `(organization, pbi_id)` (ruling: PBI ids are unique per org; `project` travels inside for the bell's target).
- `SubmitOptions` gains `#[serde(default)] pub pre_existing: Vec<i32>` and `#[serde(default)] pub hold_sigs: Vec<String>` (one per `queue` row, the webview's `holdSignature`; Rust stores them, never recomputes).
- Event (`events.rs`, registered in `collect_events!`): `pub struct UploadEnded { pub organization: String, pub pbi_id: i32 }` → `events.uploadEnded`.
- Commands (bindings names; all `Result` so the webview gets the `status` form): `upload_journal_read(organization: String, pbi_id: i32) -> Result<JournalRead, String>` → `commands.uploadJournalRead(organization, pbiId)`; `upload_journal_clear(organization: String, pbi_id: i32) -> Result<(), String>` → `uploadJournalClear`; `upload_journal_list(organization: String) -> Result<Vec<UploadJournal>, String>` → `uploadJournalList`. All three pass `crate::cache::owner()`; with no `directory()` read answers `None`, list `[]`, clear `Ok(())`.

Rules pinned:
- `journal_for_submit`: titles = every row with `update_id == None`, in queue order; `sigs` = those rows' `hold_sigs` entries when `hold_sigs.len() == queue.len()`, else `[]`; `ids` = `pre_existing` deduped in order; `None` when there are no creates.
- `read_in`/`list_in`: a file whose `owner` differs is invisible (`None` / skipped); `clear_in` with another owner leaves the file and answers `Ok(())`. `read_in` answers `Running` when `is_running(org, pbi)`, before touching the file; `list_in` skips running keys and other orgs; an unreadable file is skipped with an `applog::warn` that names no path.
- `submit_queue`: right after `single.claim()`, hold a local Drop guard that owns `mark_running(&organization, pbi_id)` and, on drop, drops the mark **first** and then emits `UploadEnded` (every exit, panic included). The journal is written after the `Submitting {total} test case(s)` log line and before `let mut results`, using `upload_since`: `if let (Some(dir), Some(j)) = (upload_journal::directory(), journal_for_submit(...)) { if let Err(e) = write_in(&dir, &crate::cache::owner(), &j) { applog::warn(...) } }`. A write failure logs and the upload goes on. Rust never calls `clear_in` from `queue.rs`.

  export function holdFromJournal(j: UploadJournal): UploadHold;
  // { since, titles, ids, sigs } ; sigs omitted when j.sigs.length !== j.titles.length; no `ambiguous`
  export function mergeHolds(existing: UploadHold | null, add: UploadHold): UploadHold;

  export type RecoverOutcome = "none" | "running" | "recovered";

- `mergeHolds` rules (ruling: "union" is a multiset max, so a journal left beside a hold saved from the same upload never doubles a row): `existing == null` returns `add`. `since` = the earlier by `Date.parse`. `ids` = `[...new Set([...existing.ids ?? [], ...add.ids ?? []])]`. When both have `sigs`, rows are `(title, sig)` pairs and each distinct pair appears `max(countInExisting, countInAdd)` times, existing order first then new pairs; otherwise `sigs` is dropped and titles merge by `max` count per title. `ambiguous` = existing's, kept only if present.
- `recoverJournal`: returns `"running"` when `submitPhaseSnapshot()` is non-null (no IPC); reads; `running` → `"running"`; `none` or error → `"none"`; `found` → re-check `submitPhaseSnapshot()` (non-null → `"running"`), `saveHold(org, pbiId, mergeHolds(loadHold(org, pbiId), holdFromJournal(journal)))`, then `await commands.uploadJournalClear(org, pbiId)` (an error is logged with `logUi`, never shown), returns `"recovered"`.
- `QueueSection`: `submitQueue(..., { order_hint: orderHint, allow_plain_steps: allowPlainSteps, pre_existing: preExisting, hold_sigs: toSend.map(holdSignature) })`. Right after `applyOutcome({...})` inside the `try`, and before `submitFinished` in `finally`: `const cleared = await commands.uploadJournalClear(org, pbiId); if (cleared.status === "error") logUi(...)`. A recovery effect keyed on `[org, pbiId]` calls `recoverJournal` on mount and again on each `events.uploadEnded` whose `organization === org && pbi_id === pbiId`.
