# MCP-in-app Plan — fold tcm-mcp into v2.exe, one-click registration, AI Bridge tab

**Goal:** (1) `v2.exe --mcp` runs the MCP stdio proxy so the separate
`tcm-mcp.exe` disappears; (2) the app detects installed AI tools (Claude
Code, Claude Desktop, VS Code/Copilot, Cursor, Windsurf) and registers the
MCP server in them with one click; (3) a new **AI Bridge** tab in the Test
Case Manager sidebar hosts status, registration, and a how-to guide —
replacing the Settings section.

## Global constraints

- No new crates. `serde_json` for config merges; `std::process::Command`
  with `CREATE_NO_WINDOW` (see existing git calls for the flag pattern) for
  CLI probes.
- Registration merges are **non-destructive**: read the tool's config JSON,
  add/replace only our `tcm-testcases` entry, preserve everything else,
  write back. Never truncate a config we failed to parse — return an error
  instead.
- Security invariants unchanged: the proxy still only reads the handshake
  file and forwards to the loopback bridge.
- Gates per task: `CARGO_TARGET_DIR=target/gate cargo test` and, when TS
  changes, `cd v2 && npm test` + `npx tsc --noEmit`. Exit codes checked.
- `v2/src/bindings.ts` regenerates via cargo test — never hand-edit;
  commit it when it changes.

### Task 1: `--mcp` mode in the main exe; delete the tcm-mcp bin

**Files:** `v2/src-tauri/src/main.rs`, `v2/src-tauri/src/mcp.rs`,
delete `v2/src-tauri/src/bin/tcm_mcp.rs`, `v2/src-tauri/Cargo.toml`,
`v2/scripts/pack.ps1`, `v2/src-tauri/src/commands/ai_bridge.rs`,
`v2/src-tauri/tests/tcm_mcp.rs`.

- Move everything in `src/bin/tcm_mcp.rs` (handshake read, `read_version`,
  the blocking-reqwest `call` closure, the stdin line loop) into a new
  `pub fn run_stdio_proxy()` in `src/mcp.rs`, keeping `handle_message`
  pure as-is. The moved code is proven — relocate, don't rewrite.
- `main.rs`: FIRST thing in `main()`, before the Velopack hooks:
  `if std::env::args().any(|a| a == "--mcp") { v2_lib::mcp::run_stdio_proxy(); return; }`
  (the proxy is spawned per AI session — it must not run installer hooks
  or touch the GUI).
- `Cargo.toml`: delete the `[[bin]] tcm-mcp` block AND the
  `default-run = "v2"` line (single bin again). Keep reqwest's `blocking`
  feature — the proxy now lives in the lib.
- `pack.ps1`: remove the tcm-mcp.exe staging block added on 2026-07-25.
- `commands/ai_bridge.rs`: `mcp_exe_path()` now returns the CURRENT exe
  path (`std::env::current_exe()`), not a sibling file. Field name
  `mcp_exe` stays (no bindings change).
- `tests/tcm_mcp.rs`: the pure `handle_message` tests stay untouched.
- Verify: `cargo build` produces only v2.exe;
  `printf '{"jsonrpc":"2.0","id":1,"method":"initialize","params":{}}\n' | target/gate/debug/v2.exe --mcp`
  answers on stdout and exits cleanly on EOF (no window, no Velopack side
  effects).

### Task 2: AI-tool detection + registration commands (Rust)

**Files:** new `v2/src-tauri/src/ai_tools.rs`, new
`v2/src-tauri/src/commands/ai_tools.rs`, `commands/mod.rs`, `lib.rs`
(module + `collect_commands![]`), new `v2/src-tauri/tests/ai_tools.rs`,
regenerated `v2/src/bindings.ts`.

- `ai_tools.rs` (pure logic, testable with injected base dirs):
  - `ToolSpec { id, name, config_path(home,appdata) -> PathBuf, install_marker(s), entry_key }`
    for: `claude-code` (marker: `claude` on PATH or `~/.claude` dir;
    registered via CLI, see below), `claude-desktop`
    (`%APPDATA%/Claude/claude_desktop_config.json`, key `mcpServers`),
    `vscode` (`code` on PATH; `%APPDATA%/Code/User/mcp.json`, key
    `servers`), `cursor` (`~/.cursor`; `~/.cursor/mcp.json`, key
    `mcpServers`), `windsurf` (`~/.codeium/windsurf`;
    `~/.codeium/windsurf/mcp_config.json`, key `mcpServers`).
  - `detect(home, appdata, on_path: &dyn Fn(&str)->bool) -> Vec<DetectedTool>`
    where `DetectedTool { id, name, installed, registered }`; `registered`
    = the tool's config file exists and contains `"tcm-testcases"`
    (for claude-code: `~/.claude.json` contains it).
  - `merge_entry(existing_json: &str, key: &str, exe: &str) -> Result<String>`
    — parses, inserts `"tcm-testcases": {"command": exe, "args": ["--mcp"]}`
    under `key` (creating the object if absent), pretty-prints. Errors on
    unparseable input (never clobber).
- `commands/ai_tools.rs`:
  - `detect_ai_tools() -> Vec<DetectedTool>` — real home/appdata dirs,
    PATH probe via `where <cmd>` with `CREATE_NO_WINDOW`.
  - `register_ai_tool(id) -> Result<(), String>`:
    - `claude-code`: spawn `claude mcp add --scope user tcm-testcases -- "<current_exe>" --mcp`
      (**user scope** so it works regardless of cwd; `claude` may be a
      `.cmd` shim on Windows — spawn via `cmd /C`), `CREATE_NO_WINDOW`,
      surface stderr on failure.
    - others: read config (empty object if the file doesn't exist yet but
      the tool is installed), `merge_entry`, create parent dirs, write.
- Tests (`tests/ai_tools.rs`): `merge_entry` preserves unrelated servers +
  replaces an existing tcm-testcases entry + errors on invalid JSON;
  `detect` against a temp-dir fake layout finds installed/registered
  states correctly.
