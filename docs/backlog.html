The rest of the 10 November 2026 assessment after A1, together with the suggestions from the second assessment in the same session. Nothing here is agreed yet; overlapping ideas are merged into one line.

Features with high impact

  • F1 Excel/CSV import and export. Declined 11 November 2026: JSON is the chosen import and export format and stays the only one.
  • F2 Scheduled and unattended Auto Run. Declined 14 November 2026: not needed.
  • F3 Trend and traceability reports. Declined 14 November 2026: not needed.
  • F4 Azure DevOps test features. Shared steps are kept but cannot be edited or expanded (steps_xml.rs). Test parameters (data-driven cases) and test configurations are not supported.
  • F5 A screen for saved setups. Only an assistant can use saved setups today (get_kept_actions, save_setup, list_setups, run_setup).
  • F7 Optional usage counts. No telemetry, so nobody knows which features are used. A local count the user can turn off is enough.
  • F9b Where Recent activity lives. Hidden from Auto Run in 2.4.6-beta.10 at the owner's request (code and tests kept): the owner is deciding where the section belongs before it is shown again.
  • F10 Share Auto Run knowledge between people. Areas, recipes and the API library appear to live on one machine and move by export file, so each teammate rediscovers the same app. Confirm first, then consider a shared location such as a repository folder.
  • F11 Audit existing test cases with the quality warnings the upload queue already applies to new ones.
  • F12 A second sign-in inside one app (several recipes per project), deferred in the sign-in build; only if a real site needs it.

UI and UX

  • U1b Undo for removing rows that came from a watched file. Undo for queue removals, Remove all and bulk edits shipped; removing rows that came from a watched import file still has no Undo, because the file write-back can edit or remove an entry but not put one back. Needs the Rust write-back to re-insert at the old position.
  • U2 Actions in the command palette. Ctrl+K only goes to screens. Add actions (import a file, upload the queue, new case, refresh) and a search for PBIs and case ids.
  • U3 Simpler navigation. Up to 12 tabs; Manual Entry, Import, Update, View, Search Suites and Suite Management overlap, and Run Tests and Auto Run are easy to confuse. Think about one Cases screen with modes.
  • U4 Fixed Ctrl+number shortcuts. The Ctrl+1 to 9 slots move when a module is turned on or off (App.tsx). Give each screen a fixed number.
  • U5 Arrow keys in Search Suites. A1.8 added them to View, Update and Run Tests; the Search Suites tree still takes clicks only.
  • U7 Translation. All text is English in the code. Only if teams outside English-speaking ones will use the app.
  • U8 An Auto Run readiness checklist. Environment, address, accounts, sign-in, areas and test files are separate rows; one checklist that says what is missing and what to do next.
  • U9 Explain the jargon where it appears. Recipe, fixture, flow, area, component, quirk, divergence and ruling: an inline definition on first use.
  • U10 Show tags in Run Tests. Search matches tags but the rows show none; add tag chips or a tag filter, and say so when the tag read failed instead of silently matching nothing.
  • U11 Error messages with a next step. The sign-in errors now say what to do; give the older ones (for example "The signed-in check never appeared") the same pass.
  • U12 Shorter changelog in Settings. The full history renders about 24,000 px tall; show the last ten versions and load the rest on demand.

Maintainability and engineering

  • M5 One markdown renderer, one UI kit. Two markdown paths (marked + DOMPurify, and Astryx Markdown) and two kits (xiod-ui and Astryx), plus hand-made controls.
  • M8 Code signing. The release script has no signing step and update trust rests on HTTPS to GitHub. Signing also removes SmartScreen warnings and the antivirus block each new build meets on this machine. Skipped by an earlier decision; worth revisiting as users grow.
  • M9 Product coupling. PeoplesHR is named in 23 Rust files (sign-in recipe, single-session rule, Playwright layout, WebForms postback). A cost only if another product must be tested.
  • M10 A scripted smoke run for hand checks. Most features since 2.3 owe live-site checks. One fixed test project and environment covering sign-in, a run, an upload and a proposal would replace most of them.
  • M11 Smaller assistant guides. autorun/guide.rs is about 205 KB; log which sections agents request and serve smaller per-job guides.
  • M12 A flaky-test log. Two load-related failures this session (App.test.tsx, bridge_per_env); a short record stops each being re-diagnosed.
  • M13 Dev app beside the installed app. Give development builds their own single-instance identity so TCM need not be closed to debug.
  • M15 Check the Run Tests tag read goes through the cache rather than fetching on every list load.
