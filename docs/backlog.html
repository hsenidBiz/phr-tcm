Crystal Reports module (2.2.3-beta.4, 17 October 2026)

For your re-implementation (TCM does not patch it)Your side
  • Live data runs EXEC [<whole name>], so a procedure stored with a schema or database in front (dbo.MyProc) is not found on the server. The six samples use plain names.
  • Subreport data is never fetched live; only the main report's procedure runs. If a future version passes the live scope to subreports, tell me before I copy it in: TCM's safety check only covers the main report's procedure today.
  • A report's saved parameter values are never bound: an unsupplied parameter is sent as NULL, though the comment in rpt-db-mssql/src/lib.rs says saved values "are consulted first". TCM refuses a live preview when a required parameter is not passed.
  • No compare function in the library; TCM carries a copy of the one in rpt-cli.
  • You plan a raw viewer so the preview no longer goes through a PDF (2026-10-17). When it exists, tell me and TCM's page view switches to it.
  • Placeholders for fields with no data (for example "[Employee Name]") would need a render option on your side.
  • The comment in rpt-core/src/preview.rs (around line 143) says subreports share the live scope; they do not today.
  • Already known limits, passed on to the assistant: text with embedded fields, subreport internals, paper size without a saved printer, password-protected reports.
Decision for you: procedures named sp_...Waiting on you

Your own procedures, views and functions named sp_... or xp_... are refused (SQL Server looks for those names in master first), so a report procedure with such a name can't be created, altered or previewed live through TCM. Allow them when written with a non-sys schema (dbo.sp_x)?

Not fully done in TCMFollow-ups
  • A request over 64 KiB is refused by the AI Bridge, so a procedure body over about 60,000 characters can't be sent (the guard itself allows 200,000).
  • XML methods written T.c.value(...) are refused (they read as a three-part name). The refusal suggests (T.c).value(...), not yet confirmed on SQL Server; c.value(...) is the other candidate.
  • Refused on purpose inside a procedure: CREATE INDEX on a temp table, ALTER TABLE #t DROP COLUMN, OUTPUT ... INTO a real table, WITH EXECUTE AS. SQL text with a carriage return on its own (old Mac line endings) is refused everywhere.
  • A slow render or live fetch holds the open report, so other report calls wait for it (up to about a minute for a live fetch that can't connect).
  • Small polish left from the reviews: Open in Crystal Reports says "no program" for any opener failure; the screen re-fetches the whole PDF on every change; a file deleted while the screen is open is only noticed on the next change; a new report whose write fails can leave a partial file.
