## The generated bindings shape (Phase 1 code depends on this)

`tauri-specta 2.0.0-rc.25` + `specta 2.0.0-rc.25` + `specta-typescript 0.0.12`:

- Command names are camelCased: `auth_status` → `commands.authStatus()`.
- Infallible commands return a plain `Promise<T>`.
- `Result<T, E>` commands return `Promise<{status:"ok", data:T} | {status:"error", error:E}>`
  — call sites unwrap and `throw` inside the TanStack Query `queryFn`.
- specta REFUSES `u64`/`i64`/`usize` in exported types (BigInt precision) — use
  `u32` etc. on any struct crossing IPC (hit this with `RateLimited.retry_after_secs`).
- Bindings are regenerated by `cargo test --test bindings` (deterministic, committed).

## Windows gotchas discovered (they will bite again)

1. **`cargo test` + tauri = STATUS_ENTRYPOINT_NOT_FOUND at test-exe startup.**
   Test binaries import `TaskDialogIndirect` (comctl32 **v6**) through tauri
   deps, but only the app binary gets tauri-build's manifest. Fix in place:
   ALL Rust tests live in `tests/` (integration targets); `build.rs` injects a
   Common-Controls v6 manifest via `cargo::rustc-link-arg-tests`; lib and bin
   have `test = false`. Do NOT add `#[cfg(test)] mod tests` inside the lib —
   the lib unit-test binary would crash at startup again.
2. **reqwest 0.13 defaults to rustls/aws-lc**, which wants CMake+NASM on
   Windows. We use `--no-default-features --features json,native-tls,form`
   (SChannel). `.form()` needs the `form` feature now.
3. **cargo add picked Tauri-1-era crates** for specta/tauri-specta; the
   Tauri-2 line is pinned: `=2.0.0-rc.25` for both.
4. **Stale cargo sparse-index cache** produced bogus "no matching version"
   errors (native-tls, openssl, system-configuration). Fix: delete
   `~/.cargo/registry/index/*/.cache` and retry.
5. **Root .gitignore ignores `package.json` globally** (local tooling);
   `!v2/package.json` / `!v2/package-lock.json` re-include the real ones.

## Deviations from the Phase-0 plan

- TLS: native-tls (SChannel) instead of rustls — Windows-first, avoids the
  aws-lc-sys native toolchain. Revisit only if cross-platform ever matters.
- Rust test layout: integration tests in `tests/` instead of in-module unit
  tests (forced by gotcha #1). `pkce`/`b64url`/`upn_from_id_token` are `pub`
  because of this.
- Tauri also produced MSI + NSIS bundles (default `bundle.targets: "all"`);
  Velopack remains the distribution channel, the others are ignored for now.

## Open risks carried into Phase 1

- **No token refresh yet**: Phase 0 tokens die after ~1 h; Phase 1 must port
  the refresh-token/silent-renew semantics from `token_manager.py` (store the
  refresh token in Rust memory, refresh before expiry, surface re-auth needed).
- Live AAD flow untested end-to-end (pending user, above). CAE / conditional
  access edge cases unknown until tried.
- WebView2 runtime assumed present (Win11 default); installer-level bootstrap
  is a Phase 5 concern.
- Frameless/custom window chrome not attempted (Phase 1 or later; decorum).
- No rate limiter yet on AdoClient (token bucket 2/s planned when writes come
  in Phase 2).
